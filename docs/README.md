# SaiWorks 文档

SaiWorks 是本地智能体执行框架（Agent Harness），长期目标为受控执行平台。命令行（CLI）、终端界面（TUI）与 Tk 桌面参考应用共享运行时（Runtime）；已有代码不等于真实 GUI、远程平台或所有故障场景已验收。

## 从哪里读

- 想知道系统职责：[架构](architecture.md)。
- 想知道现在能做什么：[当前实现](implementation.md)。
- 想决定接下来做什么：[唯一工作队列](roadmap.md)。
- 想理解机制或查接口：按下面目录进入，不从历史审查反推当前行为。
- 想运行真实模型验收：[验收入口](evaluation.md)。

## 命名规则

- 标题、工作项和依赖直接使用中文对象与能力名称，例如“任务快照与观察”“审批等待与续跑”“独立运行服务”“桌面快捷入口”。不用单字母阶段、字母数字批次或内部里程碑代替含义。
- 工作队列以完整名称标识事项，依赖用「工作名称」引用；改名须同步依赖。名称表达能力或目标，状态放在独立状态列，不混入名称，也不另设一套编号让读者查表。
- 文件名使用稳定的小写英文主题词和连字符，例如 `desktop-scope.md`、`approval-resume.md`；不把阶段、进度或未发布版本写进主题文件名。目录索引用 `README.md`，历史证据用日期加事件主题。
- 版本号只表示真实软件发布或数据格式版本；历史里程碑编号只在历史材料中保留，当页解释中文含义，不回流为当前工作名称。
- 普通说明优先中文。命令行（CLI）、终端界面（TUI）、运行时（Runtime）、模型推理服务（Model Core）首次出现时说明含义；已知产品名与标准协议名保留，避免为同一概念反复换别名。
- “交互界面”指命令行、终端和桌面等人与系统交互的入口；“Shell”只指 Bash 等命令执行环境，二者不能混称。
- 代码标识、配置项、日志事件和接口字段保留准确原名，以行内代码标明，便于核对；不能为了文档命名统一而改动接口或把新名称写成已发布字段。

## 写文档的约束

1. 修改前选择已有权威文档；能补原文就不新建专题。确需新文档，必须有独立问题、唯一职责和所属目录索引，不能只因一次会话或一次提交新建文件。
2. 禁止在路线图之外新建 TODO、progress、tracking、迁移进度或临时审查文件。专项中的机制缺口可以说明，但工作状态、优先级与实施顺序只在路线图维护，通过链接引用。
3. 当前事实必须能定位实现或验证依据。机制、接口、接入和界面说明，以及现状和验收入口页，须直接链接有效源码与相关回归入口，不能只写文件简称。链接测试文件只提供核实入口，不表示已执行或已通过。区分“已实现”“自动化已验证”“真实使用已验收”；不以文件存在、测试数量或模型自述代替验收。无法核实则明确写待核实。
4. 实现变化同步对应机制或接口、现状摘要及路线图受影响项；架构只在责任变化时更新。已完成设计合并进现行机制；重复提案和占位页删除，不保留多份正式定义。
5. 只为有独立价值的故障、可定位验证和研究保留历史材料，注明日期、源码/提交及未覆盖范围。当前文档通过历史索引引用证据，不维护阶段测试总数；发布快照保持原时点事实。
6. 移动或删除文档须更新所有仓库内入链、所属索引和锚点；文档不得依赖某台机器的相邻仓库相对路径。外部项目只在接入边界引用其权威入口，不能复制其实现或推断已完成。
7. 字段、错误码或语义变化仍须先说明兼容影响并确认。修正文档对已有行为的误述，不表示改变接口或提前批准新方案。

## 自动检查与人工核实

仓库根目录运行：

```bash
python3 scripts/check_docs.py
PYTHONPATH=src .venv/bin/python -m pytest -q tests/test_documentation_policy.py
```

检查器覆盖本地链接与锚点、目录索引可达性、中文主题名称、禁用的阶段代号与文件命名、设计状态声明、源码与回归入口、单一路线队列及工作依赖。它不验证业务语义或真实 GUI/模型效果；源码与证据交叉核对仍由修改者负责。文档检查通过不能被写成运行时功能验收通过。
