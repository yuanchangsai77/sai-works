# SaiWorks 文档

SaiWorks 的长期定位是 **Execution Core / Agent Execution Runtime**：把模型提出的意图和动作建议，转化为可授权、可执行、可验证、可恢复、可审计的现实操作。Coding 是当前主要应用场景；CLI 和 TUI 是当前交互壳。

## 阅读顺序

1. [总体架构](architecture.md)：最新定位、系统责任、目标领域与状态所有权。
2. [当前实现](implementation.md)：当前代码已经具备的机制，以及与目标的差距。
3. [演进路线](roadmap.md)：演进依赖、近期工作和验收条件。
4. 按问题阅读下面的机制、接入、交互和参考文档。

## 文档状态与权威来源

| 状态 | 含义 | 权威来源 |
| --- | --- | --- |
| 目标基线 | 已收敛的定位与责任边界，不表示能力已实现 | 总体架构 |

| 待实现设计 | 目标机制或方案，不能直接作为现行 API | 专项设计 |

| 历史 | 发布快照、精选故障与研究，不定义当前行为 | versions / archive |

目标基线不能覆盖现有接口行为。字段、错误码和配置以已实现的参考文档与代码为准；冲突应记录并核对，不能把目标直接当成实现。历史测试结果只证明注明时间与环境下的结果。

## 文档维护原则

- 架构描述职责和所有权；当前实现记录代码事实；路线图维护差距和验收，不重复专题语义。
- 同一机制只有一个权威定义，其他文档引用它。当前实现与待实现内容必须明确区分。
- Model Core 的部署、路由、调度、计量等设计由其独立仓库维护；本仓库只维护 SaiWorks 的依赖边界。
- Interface 侧接口、模型访问边界、能力接入扩展点是不同边界，不统称为同一套“运行时接口”。
- 当前正文按六个运行时领域、接入边界、交互壳与目标机制组织。过期与重复内容直接删除，归档仅保留精选故障与研究。
