# Workspace

状态：领域基线与当前实现。Workspace 是 Agent 获得资源、能力和约束的运行环境；当前路径与会话状态是它的实现起点，不是完整目标对象。

## 目标责任

Workspace 关联资源、文件、仓库、运行环境、权限、秘密引用、会话、任务和证据。软件项目、研究项目、服务器和设备环境是可能的实例，不要求每个实例都拥有 Git 或代码目录。

| 概念 | 责任 |
| --- | --- |
| 资源环境 | 可使用什么资源及其位置 |
| 环境与运行条件 | 操作需要的执行环境与限制 |
| 授权范围 | 已获准的访问和动作范围 |
| 会话与任务关系 | 哪些运行使用该环境 |
| 证据关联 | 证据对应的任务与资源版本 |

秘密引用不意味着将凭据值放入会话、提示词或检查点。身份与访问凭据归共享信任边界，Workspace 只关联必要事实。

## 当前工作空间机制

持久化会话保存初始根、活动根和批准路径。任务检查点保存进度与证据；会话授权的生命周期不应被任务结束隐式撤销。恢复使用保存的工作空间状态，中断也保留已经发生的授权。

普通外部访问只增加批准范围，不改变相对路径基准。明确打开新工作空间才改变活动根，刷新规则和项目上下文，并清理跨环境的工具去重状态。每次文件操作仍需重新解析与检查路径。

初始根继续是同一会话的有效范围。创建新会话不会自动继承旧会话的外部批准路径。结构化文件工具以活动请求根为基准，Shell 内部 cwd 另作运行状态投影。

## 当前项目适配

软件项目规则、摘要、显式上下文和测试命令探测是当前 Workspace 的场景适配，不应成为通用内核的必选功能。相关加载和预算见[上下文](context.md)。

切换活动根时持久 Shell 需要跟随新的默认环境；普通 Shell 内部 cd 不等于打开 Workspace，见[Shell](shell.md)。

## 目标与差距

目前没有完整的资源环境管理对象、远程 Workspace、统一 Secret Reference 生命周期或分布式资源同步。演进应先明确资源身份、环境关系和授权所有权，再设计持久字段。

验收应覆盖跨工作空间同名文件不复用旧观察、恢复不丢失约束、不从授权路径推导任意动作权限。当前路径机制不能被扩写为资源隔离保证。
