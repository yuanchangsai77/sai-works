# 智能体运行时

状态：领域基线与当前实现。Agent Runtime 负责持续工作，不负责推理资源调度、终端展示或绕过执行门禁。

## 领域对象与所有权

| 对象 | 语义 | 当前实现 |
| --- | --- | --- |
| 智能体（Agent） | 在约束下推进任务的运行主体 | 以引擎及独立子会话运行体现，尚无完整通用 Agent 管理对象 |
| 任务（Task） | 目标、完成要求、进度和阻塞 | TaskCheckpoint 保存有界投影，复杂依赖图仍待设计 |
| 会话（Session） | 持续交互、工作空间关系与授权的容器 | 已有持久化会话和恢复状态 |
| 运行（Run） | 一次推进任务的运行过程 | 请求、预算、事件、终态与结果汇总 |
| 轮次与步骤（Turn / Step） | 模型交互轮次与执行步骤 | 引擎循环及逐轮轨迹；不是独立服务 |
| 动作与观察（Action / Observation） | 候选操作及其观察结果 | ToolAction / ToolResult；实际执行归 Execution Runtime |

Session、Task 和 Run 的生命周期不能互相替代。一次 Run 结束不意味着 Session 结束，也不必然意味着 Task 完成。模型消息是建议或观察，不是权威状态。

## 当前推进机制

运行开始时加载规则和明确上下文，恢复已保存的能力激活，打包有界工作集。模型返回文本与动作后，Runtime 解析提案，经执行路径获得结果，再更新任务检查点和下一轮上下文。

模型声明完成后仍需核验明确要求的完成证据；不从修改意图自动推导必须写入。运行时结合必要证据、阻塞和执行结果计算终态，不能以最后一句回复覆盖失败。能力本轮激活后，从下一模型轮次开始可见。

任务检查点阶段、一次运行的终态及持久化提交状态是不同层级，不能按名称互换。实际名称、已有字段和迁移规则只维护在[运行状态参考](../reference/runtime-state.md)与[任务接受参考](../reference/runtime-acceptance.md)，本页只说明各自责任。

## 内部职责与状态所有权

| 所有者 | 当前职责 | 不承担 |
| --- | --- | --- |
| Runtime / TaskStore | 接受、提交、取消决定、审批记录、revision 与持久化通知排序 | 不把展示回调当权威状态 |
| Task 级 ExecutionContext | 绑定的取消、工具与动作账本 | 不跨 Task 共用具体批准和工具状态 |
| RunState / model_turn | 每次 Run 的预算、尝试、去重、进度及模型请求 | 不新建提交来绕过取消或任务预算 |
| ActionFlow / ToolRegistry | 准入、执行、可信阶段、观察归档及有序结果 | 不从远端 metadata 推导执行资格 |
| ResultRecorder / turn_decision / finalize | 一次性会话投影、轮次裁决和引擎终态 | 不覆盖 Runtime 的持久化与会话交付顺序 |

协调器保留装配和轮次推进；当前可见操作说明由同一内部选择器按轮装载。Run 临时计数与 Task 共享绑定分离；SessionContext 是模型工作集，不是第二套策略或任务数据库。源码见 [engine](../../src/saiworks/orchestration/engine.py)、[actions](../../src/saiworks/orchestration/actions.py)、[results](../../src/saiworks/orchestration/results.py) 和 [finalize](../../src/saiworks/orchestration/finalize.py)。

Task 取消接受与动作启动在 TaskStore 中按事务排序；已经启动的工具登记结果后再报告中断。清理只能作用于所属上下文，失败保留待重试事实，不覆盖已确定结果；单独的文件现状或进程退出不能证明历史副作用结果，未确认记录作为模型恢复事实提供，不阻塞其后续决策。可信阶段、未知动作及数据升级分别以[工具执行](../reference/tool-execution.md)和[运行控制](../reference/runtime-control.md)为准，不重复定义。

## 等待与续跑

审批和用户决策等待共用 Runtime 的持久化挂起基础。动作尚未派发时，执行循环交回内部等待事实；Runtime 将问题、原 Task/submission、当前模型轮次、剩余动作、已完成结果、观察、工作区授权、能力作用域及已用预算在同一事务保存，再清理普通工具状态并让出执行槽。保存失败不执行待决定动作，也不发布已等待或已完成状态。

续跑只恢复仍指向原规范目标的工作区授权；批准后或等待期间路径被符号链接替换时，不将授权转移给新的目标，由原有路径检查请求新的授权。恢复准备期间收到用户中断或预算耗尽时，以已保存检查点生成终态，保留已完成结果，不使用准备阶段的临时空会话。实现与回归入口：[续跑恢复](../../src/saiworks/orchestration/continuation.py)、[运行等待测试](../../tests/test_runtime_waiting.py)。

其他会话可使用空闲槽，同会话后续提交不能越过前序等待任务；领取续跑执行权仍由任务库事务裁决。取得执行权后恢复原轮次，重新校验工具可见性、参数、政策、路径和批准，直接处理原来确定的剩余动作，不额外调用模型生成已确定动作，不重放此前已完成步骤。原轮工具可见集与当前可用工具取交集；等待不构成新的模型轮次，不能让本轮刚激活的能力提前可用。等待不增加模型尝试或执行耗时；预算保留且继续生效。已完成结果和模型调用/回执配对一起恢复，用户答案成为原调用的工具结果。

续跑材料是版本化 JSON 数据，不包含线程、窗口、回调、连接或进程对象。日志暂存并恢复原 run 身份，等待不写终态。新进程可显式装配 Runtime、重新取得本地控制资格后回复并推进已保存等待；没有后台 worker 或无人值守自动续跑。会话交付仍受已有 pending/completed 约束，任务执行完成不自动证明会话消息已交付。

工具清理失败保留等待记录，恢复前重新清理；不把失败当作已停止。Shell 环境和普通工具内存状态不复活，能力从已保存身份按原作用域重新装载，资源及补丁前置条件仍重新校验。原工具不能恢复时提供真实失败，不能改用更大权限能力或重放历史副作用。该机制不保证任意外部资源或模型连接可恢复。

显式续跑同样核验已接受请求与当前委派资格，不能借接受记录绕过子代理范围。恢复准备尚未进入模型—工具推进循环时发生普通异常，归还执行权并保留原续跑材料、回复及批准，不写成缺少结果的终态。Shell 只保存最后已知目录，在新执行环境中重新校验该路径；变量、函数等状态丢失会作为检查点事实交给模型，依赖旧 Shell 状态的待执行步骤返回既有适应反馈后由模型重定，不盲目执行，也不阻止模型选择其他方案。

CLI/TUI 和桌面的同步兼容回调均在执行槽外收集决定，之后提交 Runtime 裁决；桌面提问可自由输入，关闭问题按取消处理。各界面完整迁移到快照订阅、跨界面接管及子代理人类问题转交仍有剩余边界，见[剩余设计](../design/approval-resume.md)。

## 预算与干预

当前运行限制模型轮数、请求尝试数和连续超时；总运行时间默认不设上限，可显式配置。模型传输重试增加尝试数，不等于一个现实动作已经安全重试。用户取消会触发引擎取消与工具状态清理；当前交互输入和干预仍有界面侧协调。

显式启用总运行时间上限时，同步等待用户审批的时间单独计量，不消耗该预算；模型请求、重试退避与工具执行仍计入其中。单次模型请求超时、传输重试和连续超时熔断始终生效。分析和修改任务都检测重复的既有观察，并提供一次事实反馈；同一重复阶段不反复追加控制提示，也不因再次重复、连续测试失败或连续动作被拒绝而提前终止推理。新的观察可以开始新的反馈阶段；运行最终由模型答复、取消或明确预算收尾。该检测不授予写入权限，可能改变工作空间的 Shell 调用仍保守使读取缓存失效。

长任务、后台任务与预算应该沿用同一状态模型。未来的调度器不能通过创建新 Run 重置任务约束或绕过用户取消。

## 子代理与上下文

子代理是 Runtime 管理的独立会话，不是工具内部的隐藏 Agent。委派合同限制资源、副作用和交付要求；成员协调与证据交付见[子代理](subagents.md)。

上下文是权威状态的有界投影，不是状态数据库。完整材料与恢复所需事实分开保存，模型只能消费当前有效的工作集。见[上下文生命周期](context.md)。

## 目标与差距

目标是统一任务提交、运行控制、状态查询、干预与恢复，供不同界面使用。已提取无终端 Runtime 装配与会话协调，并实现同实例单执行槽、提交去重及任务级执行上下文。常驻 worker、复杂任务图、跨界面完整接管和跨进程自动续跑尚未实现；已保存等待的显式恢复不等于这些目标。

验收重点是终态一致、预算不可绕过、取消不被迟到结果覆盖、恢复保留约束；不能用可演示的聊天过程替代故障验收。
