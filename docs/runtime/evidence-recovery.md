# Evidence & Recovery

状态：领域基线与当前实现。证据支持完成裁决，检查点支持继续运行，历史支持审查；三者不能混为聊天记录。

## 事实与投影

| 材料 | 作用 | 当前范围 |
| --- | --- | --- |
| 工具结果 | 一次操作的实际观察 | ToolResult 及结构化运行信息 |
| Evidence | 对交付要求的可检查支持 | 类型、产生者、任务、工作区 revision 和引用 |
| Checkpoint | 下一次继续所需的有界状态 | 目标、阶段、成功动作、证据、阻塞及运行投影 |
| Run trace / 日志 | 执行过程关联与诊断 | 逐轮摘要、事件、run id 和完整材料引用 |
| Session resume state | 最近任务的恢复入口 | 保存检查点和相关会话运行状态 |

证据必须绑定任务及仍有效的资源状态。当前累积证据与 revision 有效性规则见[运行状态参考](../reference/runtime-state.md)。文本声称“完成”不能替代结构化事实；工具调用名称本身也不能证明交付要求已满足。

## 当前完成与持久化

引擎从成功结果收集证据，结合 required evidence 和 blocker 计算完成条件。工作空间变化后，过期观察不能直接用于修改或完成判断。子代理证据需要 runner 校验和绑定，再进入父任务。

所有收尾路径消费同一种 terminal summary，包括部分成功结果、错误、阻塞、artifact、检查点与工作空间状态。CLI、日志和子代理不能各自从模型最后一句重算终态。

会话存储、检查点和历史轨迹承担不同职责；提示上下文有界，不意味着可丢弃所有恢复事实。大材料通过归档与引用保留，完整记录不无限复制到每轮模型请求。

当前会话压缩会清空最近恢复入口，不能视为完整保留未完成任务检查点；具体保留范围与目标差距见[压缩与恢复边界](context.md)。

## 不需要修改时的完成路径

修改意图不强制产生写入。当前完成门禁在没有未解决工具失败、唯一缺失交付为 workspace_change、最终回复命中现有“无需修改／已经满足”说明规则，且具有同一任务、当前工作区 revision 的 read 证据时，可以清除该缺失交付。随后仍由统一终态路径计算运行结果。

这不是模型自行豁免：缺少当前读取证据、存在其他未满足要求或未解决失败时，不能通过这一例外完成。当前说明识别使用有限短语规则，不代表完整语义验证，也不会豁免显式要求的 test 或 artifact 证据。

## 恢复、重试、重放与回滚

| 行为 | 语义 | 约束 |
| --- | --- | --- |
| Resume | 从保存事实继续任务 | 重新核对资源、授权与观察有效性 |
| Retry | 再次尝试失败步骤 | 区分推理请求与现实副作用，结果不确定先核对 |
| Replay | 再现或再次执行历史过程 | 展示重放与动作重放分开；后者可能产生副作用 |
| Fork | 从某个记录建立新分支 | 状态、资源与授权继承需显式定义 |
| Rollback | 补偿或撤销已发生效果 | 依赖目标能力，不能由检查点自动保证 |

当前已有恢复与局部去重，没有完整的任意动作重放、历史分叉或通用回滚。

## Execution Ledger 目标

目标账本关联提案、授权、实际执行、结果、证据和检查点，以便 Inspect、Compare 与受约束恢复。账本是可审查事实关系，不要求不可变数据库，也不能凭日志存在宣称完整链路已完成。

详细目标见[执行账本设计](../design/execution-ledger.md)。引用访问、保留、完整性和来源校验仍需专项闭环，特别是跨会话材料不能仅凭路径获得读取许可。
