# 证据与恢复

状态：领域基线与当前实现。证据支持完成裁决，检查点支持继续运行，历史支持审查；三者不能混为聊天记录。

## 事实与投影

| 材料 | 作用 | 当前范围 |
| --- | --- | --- |
| 工具结果 | 一次操作的实际观察 | ToolResult 及结构化运行信息 |
| Evidence | 对交付要求的可检查支持 | 类型、产生者、任务、工作区 revision 和引用 |
| Checkpoint | 下一次继续所需的有界状态 | 目标、阶段、成功动作、证据、阻塞及运行投影 |
| Run trace / 日志 | 执行过程关联与诊断 | 逐轮摘要、事件、run id 和完整材料引用 |
| Session resume state | 最近任务的恢复入口 | 保存检查点和相关会话运行状态 |

证据必须绑定任务及仍有效的资源状态。当前累积证据与 revision 有效性规则见[运行状态参考](../reference/runtime-state.md)。文本声称“完成”不能替代结构化事实；工具调用名称本身也不能证明交付要求已满足。

## 当前完成与持久化

引擎从成功结果收集证据，结合 required evidence 和 blocker 计算完成条件。工作空间变化后，过期观察不能直接用于修改或完成判断。子代理证据需要 runner 校验和绑定，再进入父任务。

所有收尾路径消费同一种 terminal summary，包括部分成功结果、错误、阻塞、artifact、检查点与工作空间状态。CLI、日志和子代理不能各自从模型最后一句重算终态。

会话存储、检查点和历史轨迹承担不同职责；提示上下文有界，不意味着可丢弃所有恢复事实。大材料通过归档与引用保留，完整记录不无限复制到每轮模型请求。

当前会话压缩保留最近恢复入口中的检查点和阻塞，同时隔离压缩前的历史轨迹；继续时仍需核对任务身份、工作区和证据有效性。具体边界见[压缩与恢复边界](context.md)。

## 完成要求与模型决策

运行时只将请求中明确配置的完成证据要求和委派合同中的证据要求作为强制条件，不再仅凭修改意图推导必须产生写入。是否确需修改由模型结合事实判断，不要求使用固定的“无需修改”短语。明确要求的测试、写入或产物证据不能通过最终答复措辞豁免，工作区版本变化仍会使相关旧证据失效。

协议占位输出或缺少明确要求的证据时，运行时向模型提供反馈，允许继续修正，不按两次完成失败提前终止；运行仍受取消和明确预算约束。模型最终答复不改变真实工具结果，未解决失败仍进入统一终态裁决。等待用户决策通过显式提问工具进入独立非终态，不能按普通最终答复的措辞猜测；具体见[等待与续跑](agent-runtime.md#等待与续跑)。

## 执行状态与恢复上下文

恢复诊断作为独立运行态工作集，在每次模型推理及重试前重新投影，替换上一份诊断，不改写用户请求。运行时绑定已接收的任务身份，避免继续请求丢失原目标；压缩所需辅助模型请求不改变当前任务事实。

同一任务中，同一工具后续成功后，其此前错误从恢复提示移除，历史记录仍留在账本供核查；再次失败只展示成功之后的新错误。当前运行的未解决错误与终态汇总采用同样的工具成功替代规则，不因成功调用调整了参数而继续将此前同工具失败计为当前阻塞；其他工具的失败保留。恢复提示优先展示最近八条当前记录，并注明省略数量。成功后对应旧文件观察也退出诊断；历史工具调用与回执仍是历史，不伪装成当前故障。

续跑时，运行时从持久动作账本向模型提供操作标识、工具、开始时间、经过时长、回执状态及错误码，不附带原始命令或参数。收到错误回执与尚未记录回执分别说明；超时只表示等待超时，不能推断外部操作仍在运行或已经停止。当前文件观察也不等于执行历史证明。

账本用于提供事实，不因未决记录或历史已执行记录阻塞模型选择的新操作、审批或完成。模型根据工具输出及恢复事实决定核查、修正、重试或总结，并应准确说明尚未确认的结果。原有权限、审批、取消和任务并发控制仍然有效；运行时不会自行重放历史操作。Shell 未派发证明的范围见[Shell 适配](shell.md)。

回归入口：[test_action_journal.py](../../tests/test_action_journal.py)、[test_execution_recovery.py](../../tests/test_execution_recovery.py)。链接不表示真实模型恢复已验收。

## 崩溃后的执行权与动作结果

任务库仅在能可靠确认本机原运行所有者已退出时回收旧提交执行权，并保存回收证据。即使该提交登记过副作用动作，也可接受同任务的新提交；旧动作结果继续保持未确认，不能据此断言子进程或远端效果停止，不自动重放。仍存活的所有者、无法核实的身份及其他机器记录不自动回收；同一任务仍不能有两个运行中提交。此能力不等于自动重启 worker、恢复原调用栈或任意动作重放。

回归入口：[进程崩溃与身份检查](../../tests/test_process_recovery.py)、[逐轮事实更新](../../tests/test_action_journal.py)。

## 恢复、重试、重放与回滚

| 行为 | 语义 | 约束 |
| --- | --- | --- |
| Resume | 从保存事实继续任务 | 重新核对资源、授权与观察有效性 |
| Retry | 再次尝试失败步骤 | 区分推理请求与现实副作用，结果不确定先核对 |
| Replay | 再现或再次执行历史过程 | 展示重放与动作重放分开；后者可能产生副作用 |
| Fork | 从某个记录建立新分支 | 状态、资源与授权继承需显式定义 |
| Rollback | 补偿或撤销已发生效果 | 依赖目标能力，不能由检查点自动保证 |

当前已有恢复与局部去重，没有完整的任意动作重放、历史分叉或通用回滚。

## Execution Ledger 目标

目标账本关联提案、授权、实际执行、结果、证据和检查点，以便 Inspect、Compare 与受约束恢复。账本是可审查事实关系，不要求不可变数据库，也不能凭日志存在宣称完整链路已完成。

详细目标见[执行账本设计](../design/execution-ledger.md)。引用访问、保留、完整性和来源校验仍需专项闭环，特别是跨会话材料不能仅凭路径获得读取许可。

实现依据：[control.py](../../src/saiworks/orchestration/control.py)、[tasks.py](../../src/saiworks/sessions/tasks.py)。

回归入口：[test_execution_recovery.py](../../tests/test_execution_recovery.py)。
