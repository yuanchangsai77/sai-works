# SaiWorks 工作路线

核对于 2026-11-06。本文是唯一的当前工作队列：维护状态、优先级、依赖与完成判据，不重复机制或接口定义。已实现事实见[当前实现](implementation.md)，历史验证见[证据索引](archive/README.md)。设计方向已确认不等于所有具体接口变化都获得授权；跨 App、Cloud、Agent 字段、错误码或语义变化仍须先说明影响并确认。

## 当前阶段与依赖

当前正在建设本地智能体执行框架。无终端 Runtime、任务接受与去重、同进程任务快照与多观察者、审批记录及控制资格、Task 取消桥接和动作启动排序已有实现，不再列为从零开发工作。桌面应用是已有 Tk 参考窗口，真实图形使用与生产分发尚未验收。

主线依赖：桌面使用验收 → 按失败补齐体验；审批等待与续跑 → 统一界面观察与控制。独立运行服务需先证明确有脱离界面续跑需求，不是桌面参考应用的前置。

## 当前工作队列

状态限定为：待验收、待实施、待核实、暂缓。表内顺序表示处理顺序；暂缓项目不自动转为实施授权。验收任务没有真实证据前不得仅凭代码存在或测试数量改成完成；完成后移出队列并更新下游依赖，事实进入机制/现状，独立证据进入历史索引。

| 工作项 | 状态 | 交付范围 | 依赖 | 完成判据 | 依据 |

| 桌面使用验收 | 待验收 | 在真实模型和图形环境验证桌面基本流程 | 图形环境与真实模型 | 工作区、任务、拒绝审批、取消、关闭、历史恢复均与 Runtime 一致；长对话和键盘可操作，保留运行及视觉证据 | [桌面范围设计](design/desktop-scope.md)、[产品验收](design/desktop-product-ux.md) |

| 执行框架效果核实 | 待核实 | 核对原诊断和已落地优化的真实收益 | 原对话对应记录及已有运行数据 | 核对完成语义、发现步骤、读取批次使用及上下文开销；不把线程重叠或字符减少外推为模型平均性能 | [优化证据](archive/audits/2026-11-06-harness-optimization.md)、[真实模型验收](evaluation.md) |
| 长任务与恢复验收 | 待核实 | 依据真实失败补充长任务和不确定副作用验收 | 真实失败记录 | 每项有外部可判定标准，覆盖部分成功、失败恢复及约束保留，不使用模型自评作结论 | [验收入口](evaluation.md) |
| 外部资源按需接入 | 待核实 | 为技能文件和外部工具资源建立受控的按需加载 | 明确实际资源使用需求 | 索引、来源、逐项加载、预算及敏感内容处理走现有能力和授权路径，不建立隐藏脚本执行旁路 | [Skill](integrations/skills.md)、[MCP](integrations/mcp.md) |
| 产物与证据查询 | 待核实 | 统一产物和证据查看、访问及保留规则 | 真实查看或恢复闭环 | 核对任务/会话/资源访问，明确引用、完整性、保留与删除；不把已有引用视图当作完整账本 | [执行账本](design/execution-ledger.md) |
| 终端兼容验收 | 待验收 | 核对实际终端的显示、输入和中断兼容性 | 实际终端环境 | 核对窄屏、resize、组合字符、增量失败清理、审批中断和非 TTY；依失败补覆盖 | [TUI 边界](interfaces/tui.md) |
| 独立运行服务与桌面快捷入口 | 暂缓 | 按需支持独立运行和桌面快捷操作，不预设部署方式 | 先证明脱离界面续跑需求，完成必要契约确认 | 界面关闭后续跑，重连不重提任务，attached 实例不被界面误停；生产打包、签名、更新及无障碍另行验收 | [生命周期设计](design/interface-runtime-boundary.md)、[桌面范围设计](design/desktop-scope.md) |
| 远程执行与共享身份 | 暂缓 | 用真实远程或非编程场景验证执行目标与授权 | 一个真实远程或非 Coding 闭环 | 先验证访问与执行权限、断线、超时、崩溃及撤销，再决定节点、租约和部署协议 | [执行目标](design/execution-targets.md)、[信任域](design/trust-domain.md) |
| 执行历史与长期经验 | 暂缓 | 按需设计历史重放、任务分支、效果补偿和经验复用 | 可验证的恢复或复用需求 | 不确定副作用不盲目重放；补偿依目标能力；经验不自动升级为执行许可 | [账本](design/execution-ledger.md)、[探索边界](design/exploration.md) |
| 模型自省对照实验 | 暂缓 | 比较模型自我诊断与真实运行证据 | 用户明确恢复该实验 | 固定任务和已知问题后比较证据、误报及成本；不把模型主观反思当运行事实，不预先增加自省 API | [优化证据](archive/audits/2026-11-06-harness-optimization.md) |

## 维护规则

工作项用完整中文能力名称，依赖用「工作名称」引用，不另设编号。状态变化只改本表，专项设计保留责任、机制、约束和验收定义，不另建 TODO、progress、tracking、roadmap 或迁移进度文件。实现完成时同步现状、唯一机制或接口参考及必要证据；无法核实的条目标为待核实，不猜测完成百分比。历史与发布快照不回写成当前状态。
