# SaiWorks 演进路线

状态：基于 2026-09-30 最新定位的演进规划，不表示下列目标已经完成。当前能力见[实现对照](implementation.md)，架构边界见[总体架构](architecture.md)。

## 1. 演进阶段

| 阶段 | 能力跃迁 | 当前判断 |
| --- | --- | --- |
| Coding Agent | 在本地软件项目完成模型驱动任务 | 已有基础能力，Coding 保持主要应用场景 |
| Agent Harness | 有约束、证据与恢复地持续工作 | 当前阶段；可靠性和壳边界仍有缺口 |
| Execution Platform | 多种 Agent 在工作空间内使用受控能力与执行目标 | 下一目标，不能由增加工具数量替代 |
| Distributed Agent Runtime | 跨节点调度、租约、长期运行与故障恢复 | 远期目标，需本地语义和真实闭环支撑 |

阶段不是发布版本，也不是全量完成声明。路线以职责、差距和验收组织，不沿用旧功能覆盖百分比或未重新核对的完成标记。

## 2. 当前工作：文档基线

本轮重写定位、六个核心领域、接入、交互与目标机制，旧功能目录已移除，有价值的约束已归入对应领域。

后续文档核对重点：

- 对新领域文档持续核对代码事实与故障验收证据，避免目标语义被误标为已实现。
- 明确任务状态、授权、能力激活、工作空间和证据的唯一权威来源。
- 补齐壳边界设计；在确认前不冻结字段、错误码和网络 API。
- 引用 Model Core 的实际权威文档，不复制其平台设计。远期设备和信任设计按新责任边界逐项复核。

## 3. 近期：可靠执行与壳边界

以下是待验收工作，不继承旧路线的完成勾选。优先保护执行安全和恢复语义，再提取共用入口。

| 工作 | 依赖与范围 | 验收条件 |
| --- | --- | --- |
| 执行与完成语义核对 | 复用现有解析、校验、门禁和终态 | 非法动作不得产生副作用；正常、拒绝、中断和错误路径的完成状态一致 |
| 副作用与恢复约束 | 区分模型请求重试和现实动作重试 | 对不确定结果先核对；不可幂等动作不盲目重复；恢复不扩大授权 |
| 来源与资源信任 | Skill、MCP、子代理、外部内容和证据引用 | 外部指令不能提升权限；路径、资源和证据访问边界有故障场景验证 |
| 共用 Runtime 边界 | 将会话与运行协调从交互壳中归拢 | 前台与后台复用运行语义；终端选择和渲染不拥有执行状态；CLI/TUI 行为兼容 |
| 观察与授权交互设计 | 先梳理现有回调和事件，不先选 transport | 定义状态关联、审批等待与恢复、取消及重新观察的语义；契约变化单独确认 |
| 状态与上下文可靠性 | 复用已有检查点与预算 | 中断恢复保留约束与证据；失效文件观察必须重验；必需上下文不能静默丢失 |

门禁和故障场景随对应工作验收，不以记录测试收集数量代替实际执行。CI、静态检查和终端兼容性按实际缺口补齐。

## 4. 下一阶段：Execution Platform

先在本地验证 Workspace、Capability、Policy 和 Execution Target 的协作，再扩展远程目标。

- Workspace 从路径与会话授权提升为资源环境，明确状态所有权和秘密引用边界。
- Capability 描述与执行适配分开，复用现有仓库，保持发现、激活和授权独立。
- Execution Target 明确目标身份、约束、生命周期和执行结果；避免为每种工具建立旁路。
- Policy 消费可验证的主体与访问事实，执行授权不由网络连通性推导。
- Evidence 与执行记录建立查询和恢复关联；Replay、Fork、Rollback 分别设计与验收。

退出条件：至少一个真实的非 Coding 或远程执行闭环，经由同一授权、执行、证据和恢复路径；不同交互壳不复制业务逻辑。

## 5. 接入与交互专项

Skill 资源包、MCP resource 上下文、公网兼容性、TUI 增量展示、输入历史和配置体验仍有价值，但作为运行时或壳的专项能力推进，不重新定义系统总体架构。

相关范围见[接入地图](integrations/README.md)与[交互地图](interfaces/README.md)。已有 streaming 客户端和增量展示代码不等于所有终端和重试场景完成验收；审批代理和跨设备交互仍需单独设计。

## 6. 远期：Distributed Agent Runtime

节点注册、执行资源租约、能力发现、分布式工作空间、常驻 worker、长期任务、调度与故障协调，需要真实部署需求驱动。Model Core 管理推理资源，SaiWorks 管理执行资源；共享信任域提供访问基础，不能合并两类权限。

退出条件由具体纵向闭环定义，至少覆盖断线、超时、进程崩溃、不确定副作用和撤销。当前不承诺服务数量、wire schema、调度算法或统一回滚。

## 7. 完成与变更规则

工作完成需要实现证据、相关正常及故障场景验证、现行契约兼容性和文档同步。只在实际准备发布时增加版本快照。涉及 App、Cloud、Agent 多方字段、错误码或语义变化时，先说明影响并确认，文档规划本身不构成实施授权。
