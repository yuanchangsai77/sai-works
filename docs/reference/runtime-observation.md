# Runtime 同进程任务观察（D1）

范围：同进程任务查询及多观察者。审批、按 Task 取消和独立服务生命周期仍属于 D2/E，不在本接口中承诺。

## 接口与资格

Runtime 的可信装配方调用 `grant_task_access(task_id)` 获取仅含观察资格的不透明本地句柄。`snapshot(access)` 返回完整快照；`watch(access, after_revision=None)` 返回独立观察游标，`poll()` 非阻塞读取最新变化，`close()` 关闭游标。`revoke_task_access(access)` 撤销句柄并使其所有观察游标失效。外部输入不能调用授予入口；句柄不跨 Runtime 实例或进程传递。接口拒绝伪造、已撤销及其他实例的句柄，不通过角色字符串授予资格。

观察游标只保留上一修订位置，不积累通知队列，也不调用用户回调；生产者无需等待消费者。首次未指定修订位置时返回当前快照；没有变化时返回 None；跳过多个修订时返回完整快照并标记 resync_required。指定未来或负修订位置无效。短暂文本预览不在此接口交付。

快照数据库读取和数据还原不持有 Runtime 调度锁；读取前后均校验观察资格，读取期间撤销或关闭 Runtime 时不返回该快照。“非阻塞”表示不等待新事件或客户端处理，SQLite 读取仍可能等待数据库锁或磁盘，不承诺 UI 线程调用零延迟。

## 快照与交付

TaskSnapshot 包含 task_id、revision、state、current_submission_id 和按接受顺序排列的 submissions。每个提交包含现有 TaskRecord 的字段及 delivery_state；结果、错误和运行身份归属对应提交，不将历史错误覆盖到新尝试。聚合状态优先 running，其次 queued，否则取最新提交状态；当前提交取最早 running，其次最早 queued，否则最新提交。revision 与所有提交从同一 SQLite 读取事务取得；接受、取得执行权、提交结果、交付状态变化均在各自写事务中递增 Task revision。重复接受和无变化操作不递增。

delivery_state 区分 not_required、pending、completed。会话型或延迟交付执行在取得执行权前记录 pending；执行结果持久化后可以显示 finished，但 pending 不表示会话已交付。只有会话保存成功后才记录 completed，再发布旧完成通知。会话保存失败保持 pending，重试只补交付，不重放已完成执行。会话已保存但交付标记写入失败时，同样保留 pending 并抑制完成通知；pending 不能证明会话未保存，该窗口需要核对会话事实，不承诺跨库原子提交或自动补交付。旧记录无法证明交付是否完成，升级时标记 unknown，不伪造完成；unknown 不触发自动补执行。

快照外层为冻结的数据类，嵌套的既有结果对象为每次查询独立还原的数据；调用者修改展示副本不会修改任务库或其他观察者的数据。

同一 Runtime 内保留成功保存的提交交付凭据：交付标记失败后再次提交原请求，只重试标记，不重复保存或追加消息；completed 提交重复调用也不再次追加或发布完成通知。凭据不持久化，不作为跨进程恢复保证；进程重启后仍按已保存事实核对 pending，不自动重放执行或补写对话。

## 数据兼容

任务库增量升级到 user_version=2，增加每 Task 修订记录及提交交付字段；旧记录升级为记录版本 2，查询仍支持版本 1/2。Session JSON、ExecutionSummary、工具及模型格式不变。新程序拒绝未知数据库版本。旧程序不能读版本 2 的任务记录，升级前必须停止旧写入进程，不能并行使用旧程序写任务库；不承诺旧程序只读回退。升级事务失败保持原库可用，升级不执行任何旧任务。
