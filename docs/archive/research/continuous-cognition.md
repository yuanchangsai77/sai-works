# 连续认知与有限工作集：精选研究笔记

状态：来自早期连续认知研究的假设摘要。不是已验证模型能力，也不定义 SaiWorks Runtime 或 Model Core 的实现契约。

## 值得保留的问题

持续系统面对异步、带时间间隔的输入，不能只把所有历史无限追加到每次模型请求。如何在有限活跃工作集内持续观察、保持来源、回查原始证据并分配计算，是研究核心。

| 假设 | 需要验证的问题 | 主要责任 |
| --- | --- | --- |
| 感知、计算与可见输出可分别调度 | 是否减少无意义计算，同时保持响应质量 | Model Core 与上层运行协调 |
| 活跃工作集有界，历史分层保存 | 摘要丢失什么，哪些材料需要回查 | Runtime 上下文与存储；模型内部另行研究 |
| 临时分支可以探索不同候选 | 分支成本、来源隔离和合并冲突如何控制 | Runtime 委派；神经状态分支归模型研究 |
| 原始证据与语义记忆分别保留 | 如何验证记忆及撤销派生记录 | Evidence 与经验治理 |
| 随时间调整信息分辨率 | 哪些时序事实不能被摘要抹去 | 具体领域观察与上下文策略 |

## 与当前系统的关系

当前 ContextPackager、检查点和独立子会话为有限工作集提供工程基础，但不等于 latent memory、神经信号控制或 KV 分叉已经实现。对话分支、任务分支与模型内部认知分支是三种不同机制。

SaiWorks 管理授权、任务状态、预算、证据与恢复；Model Core 研究推理后端与计算机制。无论模型内部采用什么结构，外部动作仍经过同一执行门禁。

## 保留与删除的判断

保留持续输入、有限工作集、原始证据、分支成本及模型/运行时责任分离。删除固定 Mamba/SSM 与 Transformer 分工、Signal 枚举、latent object 结构、未验证的性能结论和重复哲学比喻；这些内容没有足够证据成为目标基线。

后续研究需要真实负载下的成本与质量对照、摘要损失、来源隔离、分支合并和撤销测试。没有这些证据，不将假设提升为当前能力或通用接口。
