## 当前数据流

工具返回先接受单项字节预算，随后 SessionContext 把输出、状态和有界参数拼成普通文本。
模型回复也只以消息文本追加；原生调用标识和完整动作结构不进入这份历史。
ModelPromptBuilder 取最近 30 条历史项，将它们与运行轨迹、恢复信息拼进同一个可裁剪片段。
ContextPackager 将检查点与该片段放到当前用户请求之后的 runtime-generated user 消息中。
下一次运行恢复的是用户/终态消息、检查点和轨迹概览，具体工具输出不会自动恢复为工作集。

## 已确认的组装问题

### P1：当前运行观察的硬上限不随空余预算增加

`context/packager.py:93` 将整个 trailing 区域限制为总预算的 10%。默认 120000 字符时约 12000 字符，检查点还先占其中一部分。
会话历史随后使用余量，但当前工具历史不会重新争取未用空间。
实际日志中请求常只有约 23000 字符，仍可能反复裁剪当前观察；这里的字符数不包含工具 schema。
单个 read_file 默认可返回 64000 字节，统一工具输出默认上限 32000 字节，之后又遇到这个更小的合并预算。

复现：给组装器一个约两万字符、可轻松放入总预算的最新工具结果，下一次输入仍不能完整保留它。
这给“模型刚读过却再次读取”提供了直接的信息丢失机制。

### P1：裁剪的是整段字符串，未保护工具结果边界

最近历史被拼接为多行长文本，再按头部/尾部保留；裁剪器不理解哪一段是调用、来源、状态或正文。
已独立复现：旧大结果头和新大结果尾被留下，新结果的文件路径头消失；夹在两个大结果间的小型关键发现完全消失。
模型收到的可能是缺少来源的代码尾部，不能把这种输入视作“已经完整提供过文件”。

### P1：恢复指令要求复用的材料没有进入恢复输入

`sessions/coordinator.py:215` 只把当前用户输入和终态摘要追加到对话。
`model/prompt.py` 的轨迹格式化只取运行号、请求、工具名称和最终消息，不消费持久化轨迹的逐轮结果摘要。
本会话第二次运行的首个完整请求直接证实：有工具名、耗尽提示和“复用上次成功结果”的建议，没有上次读取的具体内容。
新 SessionContext 的当前运行历史也从空列表开始。

这不要求把全部旧输出重新塞入提示；需要保留足以继续任务的有效发现与可回查来源，避免要求模型复用一个看不到的结果。

### P2：按 30 条字符串项截取，不能代表 30 个完整交互轮次

模型消息和每个工具结果分别占一条，双工具调用会更快淘汰早期发现。
即使总字符预算充足，一条有用的小结果也会被后续短状态消息挤掉，且没有内容摘要接替。
这与字符裁剪是两个独立的信息损失来源。

### P2：部分读取的范围与完整性信息未明确进入模型工作集

SessionContext 主要暴露 output、状态和 action_arguments；read_file 返回的实际起止行、总行数及 truncated 等元数据默认隐藏。
如果用户参数没有明确范围、输出又因读取字节预算截断，模型可能只看到一段正文，缺少“还剩多少、下一段从哪里读”的信息。
统一工具预算截断有文本标记，但不能覆盖所有 read_file 自身截断路径。
该问题可复现；尚未量化它在本会话中的独立贡献。

### P2：诊断中的“未省略消息”不能证明工具上下文完整

ContextPackageStats 已有 truncated_current 和 truncated_system，但 model.request 只记录预算、已含字符数、omitted_messages。
后者只统计持久对话的完整轮次选择，不统计最近 30 条截取和运行上下文中的字符串裁剪。
因此日志中 omitted_messages=0 与工具结果已被裁剪可以同时成立。

## 结构风险与旁路放大因素

原生工具协议的输入历史目前没有 assistant.tool_calls / tool 消息配对，而是运行时 user 文本。
这种输入不必然导致 API 报错，但会丢掉原生调用与结果的明确关系，必须作为待对照的兼容性风险，不能直接宣称它单独造成了循环。

工具说明在系统文本与 API 工具 schema 中重复；组装预算只计算 content 字符，不包含 schema、消息框架和实际 token。
这是预算精度问题，本会话没有证据证明因此撞到模型上下文上限。

无进展策略依赖 requires_file_changes 显式契约，普通会话未设置；即使“先改设计稿”也不会进入该恢复分支。
不应为了修复循环，把所有分析请求都误判为必须写文件；通用进展检测应与修改授权分开。
重复检测以完整工具参数为键，改变参数可绕开；成功 execute/test 类工具会清空缓存，读性质 Shell 也会触发此行为。
这些机制放大探索，但不改变前面信息丢失问题的成立。
