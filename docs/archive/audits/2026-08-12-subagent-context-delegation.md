## 事件依据

只读审查任务被自然语言分类误认为修改任务，触发错误进度纠正；子代理授权没有充分绑定实际副作用与资源合同。公共摘要曾以 system 消息进入其他会话，提升了不可信内容的优先级。子 runtime 先记录完成，runner 后置校验又改成阻塞，导致同一 attempt 多份状态不一致。

## 保留的教训

| 失败边界 | 应保持的约束 |
| --- | --- |
| 任务文本被当成权限依据 | 结构化副作用与资源合同，执行时再次校验 |
| 公共摘要变为高优先级指令 | 公共内容保留来源与观察身份，不获得策略权威 |
| 日志完成早于交付校验 | 先形成经校验的唯一终态，再投影到各存储 |
| 工具成功被当成任务完成 | 以交付证据判定，不按最后一个工具结果推断 |
| 旧 worker 迟到提交 | 绑定 attempt，取消或续跑后不能覆盖新状态 |

当时修复覆盖委派约束、公共状态降权、准入和终态协调等机制；审批代理、制品所有权与完整性、全链路预算仍有后续问题。历史记录不替代今天的代码核对。

## 回归场景

只读子任务不得修改；缺失或无效合同不能回退为全权限；额外权限需求只产生 blocker；模型公共摘要不能授权；输出校验失败后的 run/session/cluster 状态一致；取消与续跑后的旧结果不能覆盖新 attempt；部分成功与未解决成员必须同时可见。
