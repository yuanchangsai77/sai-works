# TUI 交互壳

状态：当前实现与验收边界。TUI 是内联终端展示适配，不拥有任务、授权或恢复的第二套状态。

## 当前组成

TUIController 消费事件队列并维护展示投影，TUIRenderer 生成终端行，TUIConsolePresenter 适配执行进度、自然语言增量、工具结果和审批。Composer 管理输入、编辑、历史与补全。

展示状态只表达当前界面需要的信息；Runtime terminal summary 才是执行终态。前端运行、工具进度或审批视图不能被直接当成完成与许可事实。

## 屏幕与输入

当前不进入 alternate screen，也不捕获鼠标。稳定内容提交一次后交由终端原生 scrollback 管理，程序不维护第二份可见 transcript；原生滚动、选择和复制由宿主终端负责。

程序只管理紧跟稳定输出的瞬态尾部，包括输入、模型预览、运行状态和审批。尾部不固定占用物理屏幕底边；刷新清理上次覆盖区域，窗口缩放时重新计算视觉行与光标位置。已完成、失败、中止或跳过的工具记录及时提交到稳定输出，不等整轮结束才集中显示。

自然语言增量留在可清除预览中；完整回复通过校验后稳定渲染，再按实际执行顺序提交该轮工具记录。终态和工具记录不能因重复刷新被重复提交。

只有交互模式且 stdin、stdout 都是 TTY 时选择 TUI。正常单次执行（--once）、重定向、非 TTY 和通常的 CI 环境使用 ConsolePresenter 逐行输出；是否使用 TUI 取决于模式和 TTY 检测，不单独依赖 CI 环境变量。流式自然语言在不可回写输出中失败时，需要明确标记已显示片段未被采纳。

会话选择、斜杠命令补全和编辑历史是壳功能。补全查看目录不应触发远端发现或激活；选择能力后仍经 Runtime 路径。

## 增量与失败

代码已有自然语言增量展示回调。增量在完整响应校验前是临时展示，失败重试需清理或标记，不进入正式会话结果。不得把动作参数或协议碎片暴露为回复正文。

存在回调与演示不等于所有终端、重试和中断场景完成验收。窄屏、resize、组合字符、重连观察、持久历史及 overlay 仍需按实际缺口验证。

## 审批与取消

TUI 展示具体操作并转交决定，Runtime 验证其范围。当前仍是同步确认适配，跨壳可恢复审批见[授权交互设计](../design/approval.md)。用户中断必须传播到引擎和活动执行，而非只清除界面。

## 演进方向

优先稳定事件与终态一致、增量失败清理、审批中断及终端兼容，再扩展 overlay 和历史查询。交互体验不成为独立内核，具体优先级见[路线图](../roadmap.md)。
