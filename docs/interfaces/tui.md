# 终端交互界面

状态：当前实现与验收边界。TUI 是内联终端展示适配，不拥有任务、授权或恢复的第二套状态。

## 当前组成

TUIController 消费事件队列并维护展示投影，TUIRenderer 生成终端行，TUIConsolePresenter 适配执行进度、自然语言增量、工具结果和审批。Composer 管理输入、编辑、历史与补全。

展示状态只表达当前界面需要的信息；Runtime terminal summary 才是执行终态。前端运行、工具进度或审批视图不能被直接当成完成与许可事实。

## 屏幕与输入

当前不进入 alternate screen，也不捕获鼠标。稳定内容提交一次后交由终端原生 scrollback 管理，程序不维护第二份可见 transcript；原生滚动、选择和复制由宿主终端负责。

程序只管理紧跟稳定输出的瞬态尾部，包括输入、模型预览、运行状态和审批。尾部不固定占用物理屏幕底边；刷新清理上次覆盖区域，窗口缩放时重新计算视觉行与光标位置。已完成、失败、中止或跳过的工具记录及时提交到稳定输出，不等整轮结束才集中显示。

自然语言增量留在可清除预览中；完整回复通过校验后稳定渲染，再按实际执行顺序提交该轮工具记录。终态和工具记录不能因重复刷新被重复提交。

只有交互模式且 stdin、stdout 都是 TTY 时选择 TUI。正常单次执行（--once）、重定向、非 TTY 和通常的 CI 环境使用 ConsolePresenter 逐行输出；是否使用 TUI 取决于模式和 TTY 检测，不单独依赖 CI 环境变量。流式自然语言在不可回写输出中失败时，需要明确标记已显示片段未被采纳。

普通提交及运行中排入下一轮的提交会立即清空 Composer 的文本、光标与历史浏览状态；历史内容只在用户主动浏览时恢复。审批选择不读写普通输入缓冲区，已有未提交草稿在审批期间保留。

会话选择、斜杠命令补全和编辑历史是界面功能。补全查看目录不应触发远端发现或激活；选择能力后仍经 Runtime 路径。

输入缓冲区与执行状态分离：普通字符和带括号粘贴只编辑缓冲区，终端字节按增量方式解码，未完成的 UTF-8 字符、按键序列与粘贴载荷由输入适配器保留，粘贴完成后统一换行；Enter 明确提交。旧式按键编码与增强键盘协议先统一解码，再进入编辑、取消或审批逻辑；支持增强键盘协议的终端使用 Shift+Enter 换行，也保留 Alt+Enter。终端输入法的预编辑由宿主处理，程序只接收提交后的字符；无法区分宿主直接发送的普通 Enter 与输入法确认键，真实输入法兼容仍需终端验收。

Composer、会话选择器与压缩确认框共用同一输入来源和增量解码缓冲；预读的后续按键由接下来的交互组件消费，选择组件忽略粘贴事件。执行期间只有一个终端读取线程，工具审批继续由该线程分发；运行中不另开选择读取者。Runtime 结束时停止读取并等待旧线程退出，再交给空闲输入框；未完成的粘贴和已解码但尚未分派的事件随输入适配器交接，不因任务结束丢失。等待用户回复时，提交交给当前同步等待回调，由既有 Runtime 回复或取消机制续跑；不会走新任务中断路径。正常运行期间编辑不打断，普通任务明确提交才沿用中断并排入下一轮的策略。`/mode` 查询与切换通过既有 Runtime 控制入口即时处理，不中断任务、不排入下一轮，也不作为挂起问题的答案；切换作用于后续权限检查，已挂起的审批仍须明确决定。审批期间仅接受明确审批按键，粘贴不会批准；输入编辑、回复交付、移除接收者与恢复原草稿在同一同步边界内完成，再唤醒 Runtime 回调；回调结束不会覆盖随后输入的内容。提示输出期间中断、取消或运行结束也会按请求身份清理接收者，后续输入不能补入旧请求。

交互输入模式关闭输入侧信号生成、流控及字符转换，保留原输出配置，退出时恢复原终端设置。Ctrl+C 由应用按当前交互语义处理；粘贴里的 Ctrl+C、Ctrl+S、Ctrl+Q 保留为文本字节。

输入中的 C0/C1 控制字符（换行除外）在编辑框与已提交消息展示中显示为可见转义，换行继续用于多行布局。光标与折行按可见内容计算；原始输入文本保持不变，终端不会把粘贴里的清屏、光标或 OSC 指令作为控制序列执行。

## 增量与失败

代码已有自然语言增量展示回调。增量在完整响应校验前是临时展示，失败重试需清理或标记，不进入正式会话结果。不得把动作参数或协议碎片暴露为回复正文。

存在回调与演示不等于所有终端、重试和中断场景完成验收。窄屏、resize、组合字符、重连观察、持久历史及 overlay 仍需按实际缺口验证。

## 审批与取消

TUI 展示具体操作并转交决定，Runtime 验证其范围。CLI 使用已有任务与提交标识区分续跑和新提交；同一轮审批或用户回复后的续跑不重新输出用户消息；独立的续跑展示事件移除上一执行片段遗留的运行中工具视图及其活动句柄，保留已完成工具记录、输入草稿与原始计时，不将挂起误标为成功或中止。恢复后的工具由新进度句柄报告结果，终态后新的提交仍正常显示。审批选择与结束事件只作用于匹配的 `approval_id`，未知或过期接收者不产生新决定。同步兼容适配在持久化等待后、执行槽外收集批准或用户答案，内核据此续跑；现行机制见[等待与续跑](../runtime/agent-runtime.md#等待与续跑)，跨界面接管仍见[授权交互设计](../design/approval.md)。用户中断必须传播到引擎和活动执行，而非只清除界面。

## 验收范围

事件与终态一致、增量失败清理、审批中断及终端兼容分别需要真实终端证据；存在演示不表示这些场景已验收。是否扩展 overlay 和历史查询由[路线图](../roadmap.md)管理，不在本页另排开发顺序。
