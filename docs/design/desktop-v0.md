# Desktop V0.1 设计与实施计划

- 日期：2026-10-01
- 状态：已确认方向，第一纵向切片已实现参考窗口
- 范围：本地、单用户、同进程 Desktop 薄壳

## 1. 产品目标

Desktop V0.1 不是将 CLI 窗口换成图形界面，而是为现有 Runtime 提供低门槛的交互壳。用户能选择工作区、输入任务、查看进度与结果、处理审批、取消当前任务并恢复历史会话，不需要理解 CLI 参数、斜杠命令或内部运行步骤。

交互方式可替换，执行效果不可分叉。CLI、TUI 和 Desktop 必须消费同一 Runtime 语义；Desktop 不持有任务终态、不自行保存会话、不缓存批准权限，也不直接调用 ExecutionEngine。

## 2. 分阶段交付

### V0.1a：同进程单壳

Desktop 在自身进程内通过 `create_runtime()` 装配 Runtime。首个纵向切片包含工作区选择、会话打开、文本任务提交、当前运行取消、终态结果和会话恢复。这一阶段可验证交互体验与壳边界，但不承诺运行中换壳、多客户端同时观察或关闭窗口后续跑。

第一批代码提供不依赖 GUI 框架的 Desktop application controller，并以 Python 环境内置的 Tk 8.6 实现参考窗口，用于验证工作区、会话、提交、审批、进度和取消纵向链路。Tk 只是 V0.1a 参考壳，不写入 Runtime 契约；长期窗口技术仍需根据键盘辅助、无障碍、打包、更新和本地进程集成验证决定。

### V0.1b：阶段 D 最小闭环

为运行中从 CLI/TUI 切换到 Desktop，实施按 Task 的一致 Snapshot、单调 revision、多观察者、慢消费者隔离、重新同步和稳定 Task 取消。审批持久化、TTL 与 continuation 依照[阶段 D 契约](runtime-sync-approval-contract.md)实施，不由 Desktop 单独维护。

### V0.2：阶段 E 常驻化

只在 V0.1 验证用户需要壳退出后继续执行时，引入独立 Runtime、实例发现、managed/attached ownership 和薄 Gateway。常驻化不是 V0.1a 开发前置，也不允许 Desktop 自己实现第二套任务恢复逻辑。

## 3. 责任边界

| 职责 | Desktop | Runtime |
| --- | --- | --- |
| 工作区 | 选择并展示 | 校验、绑定并恢复 |
| 任务输入 | 收集用户意图和显式上下文 | 接受、去重、排队与执行 |
| 进度与结果 | 渲染投影 | 生成并持久化权威事实 |
| 审批 | 显示动作并转交人的决定 | 绑定 Task + Action、校验有效性 |
| 取消 | 发送明确的任务控制意图 | 排序、传播、核对并产出终态 |
| 会话 | 列表、选择与展示 | 保存、压缩、恢复校验 |

Desktop 只依赖稳定的 application controller/Runtime 门面和不可变查询投影。GUI 事件、窗口生命周期和本地显示偏好不进入 Runtime。

## 4. 第一纵向切片验收

- controller 可无 GUI 创建或恢复会话，并通过 Runtime 提交完整一轮。
- 结果、会话和 TaskStore 使用现有 B/C 完整提交语义，controller 不额外保存。
- 当前任务取消只转交 Runtime，不把“已发送取消”显示为“已安全停止”。
- controller 只返回不可变显示状态和执行结果，不暴露 Engine、ToolRegistry 或可变 Policy。
- CLI/TUI 现有回归不受影响；新 Desktop 专项测试不需要终端。

## 5. 明确暂缓

- 生产 GUI 框架、窗口打包、签名与自动更新技术选型；Tk 只用于首个参考窗口。
- 关闭 Desktop 后任务续跑、多入口实例发现与 Gateway。
- Mobile、Voice、远程设备和被动屏幕采集。
- Desktop 自有的任务状态机、审批缓存或会话存储。

## 6. 启动与关闭

V0.1a 采用“一窗口、一进程、一 Runtime”，不引入守护进程、PID 文件、本地端口或服务管理器。`sai-works-desktop` 启动窗口并在同进程调用 `create_runtime()`；初始化失败以可读对话告知用户，不留后台进程。

正常关闭、窗口系统关闭和 SIGTERM/SIGINT 共用同一流程：

1. 无执行任务时，保存并关闭当前会话，再幂等关闭 Runtime 及工具/MCP 资源。
2. 正在执行时，先明确告知“将请求取消并等待核对”，Runtime 停止新动作并收尾，然后自动关闭。
3. 等待超时不伪称已安全停止；向用户提供“继续等待”或“强制退出，后续核对”。
4. `Runtime.close()` 可重复调用；关闭后不再接受新任务。强制关闭只用于用户确认的超时退出，取消不撤销已发生的外部副作用。

Model Core 是外部推理依赖，Desktop 首版只连接它，不暗中启动或停止另一个常驻服务。连接失败应显示为模型服务不可用，不让用户手工管理未声明的子进程。
