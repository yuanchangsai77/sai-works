# 执行引擎职责与状态收敛设计

状态：内部重构方案，2026-10-23 经独立评审修订；同进程职责收敛已实施，2026-10-28 补充 Task 取消桥接与动作启动门禁。目标是降低 `orchestration/engine.py` 的职责密度。未新增跨 App、Cloud、Agent 的接口字段或错误码；运行中取消后的 outcome 修正及其影响见[运行状态参考](../reference/runtime-state.md)。

## 1. 当前问题与边界

`ExecutionEngine` 目前同时完成运行初始化、模型请求与重试、动作预检与审批、工具执行、观察记录、进度判断、完成门禁和终态收尾。一次运行的临时计数分散在 `_execute` 的局部变量、`ExecutionContext`、`SessionContext`、工具状态和检查点中。相同工具结果在批准和无需批准的分支分别处理，容易出现状态更新顺序不一致。

本次只整理**同进程、单执行槽**的内部边界。Runtime 继续负责 Task 接受、队列、任务控制、会话协调和持久化；引擎继续负责一次 Run 的推进。跨进程续跑、可恢复异步审批、远程执行目标和新协议均不属于本次重构。

## 2. 分工：一个协调器，四个内部职责

| 职责 | 输入与输出 | 唯一可写状态 | 不负责 |
| --- | --- | --- | --- |
| `ExecutionEngine` 协调器 | 接收请求，串起初始化、模型轮次、动作处理、收尾 | 当前运行引用；执行锁 | 直接修改证据、检查点和批准记录 |
| 运行控制 | 模型调用、重试、预算、取消检查和进度停止条件 | 一次 Run 的计数、计时、重试和终止意图；读取 Task 级取消事实 | 工具副作用、Task 持久化 |
| 动作执行 | 可见性、委派范围、预检、策略、审批、工具调用 | 一次 Run 的批准缓存、动作去重缓存和路径授权 | 完成判定、会话历史追加 |
| 结果记录 | 模型回复与工具结果，形成有序观察 | `SessionContext` 的历史、观察和结果驱动的 `TaskCheckpoint` 投影 | 决定是否调用工具、决定 Run 终态 |
| 完成裁决 | 检查证据、阻塞、模型完成声明和 Run 结果 | 返回裁决和派生的交付缺口；统一收尾写入终态 | 模型调用、工具调用、日志展示 |

这四项是内部职责，可先用现有模块中的小类或函数承载；不要求四个新服务或公共接口。`control.py` 中现有预算和完成规则继续复用，避免再造一套策略。

## 3. 状态所有权

| 状态 | 权威持有者 | 生命周期 | 写入规则 |
| --- | --- | --- | --- |
| Task 接受、提交、取消决定、审批记录与修订 | Runtime / `TaskStore` | 跨 Run，持久化 | 引擎消费已绑定的控制事实；不得自己复制 Task 状态机 |
| Task 级取消绑定与执行上下文引用 | Runtime 按 Task 持有；现由 `ExecutionContext` 承载 | 同一 Task 的多个提交 | 现有共享取消语义保留；不能把取消信号当作每 Run 可重置的普通计数 |
| 一次 Run 的预算、超时、重试、去重、进度计数及终态 | 独立的 Run 控制状态 | 单次 Run | 每次领取执行时新建；运行结束即丢弃；需要恢复的摘要明确投影到检查点 |
| 活动工作区及会话级路径授权 | `SessionContext.workspace_state` 与执行权限上下文 | 会话 / Run | 成功切换工作区后先更新活动根，再登记观察；不得由模型文字直接修改 |
| 能力激活与可见工具 | `CapabilityWarehouse`；每轮开始生成可见工具快照 | 按 scope | 本轮工具可见性固定；激活后的工具下一轮才可用 |
| 运行内对话历史、观察及模型可见投影 | `SessionContext` | 当前 Run | 模型回复和每个工具结果只追加一次；合成结果也走同一入口 |
| 跨 Run 对话和恢复投影 | `StoredSession` / `SessionStore`；观察归档另行保存 | 会话持久化 | Runtime / SessionCoordinator 负责保存；运行内 `SessionContext` 不是持久化真源 |
| 任务证据、工作区修订、交付缺口和阻塞 | `TaskCheckpoint` | 跨 Run 的有界投影 | 初始化写入要求；结果记录写入执行事实与证据；完成裁决计算缺口；统一收尾写入相位和最终阻塞 |
| Run 终态及返回结果 | 引擎统一收尾生成 `ExecutionSummary` | 单次 Run | 引擎只收尾一次；Runtime 另行负责日志定稿、Task 提交、Session 保存和终态通知 |
| 日志和进度展示 | Logger / Reporter | 观察用途 | 从已发生的事实派生，不作为恢复或授权的权威来源 |

`SessionContext` 仍可承载发送给模型的上下文，但不再直接承担所有决策。`TaskCheckpoint` 是有界恢复投影，不是完整执行账本。`TaskStore` 的 Task 状态、`TaskCheckpoint.phase` 和 `ExecutionSummary.outcome` 保持不同语义，不能相互覆盖。

最小内部对象只需三种：一次运行的控制状态（计数、缓存、取消观察）、一次动作的处理结果（工具结果及其来源）、一次轮次的裁决（继续、完成或停止的理由）。它们不进入持久化格式，也不成为交互壳接口。模型和工具仍使用已有类型。当前 Runtime 按 Task 复用 `ExecutionContext`；迁移时保留 Task 级共享绑定，在其下隔离每次 Run 的计数与终态，不能直接把整个 `ExecutionContext` 改为每 Run 新建。

在 2026-10-23 职责拆分阶段，`Runtime.cancel` 只持久化取消决定，`cancel_current_run` 只设置运行中的内存信号；第 8 节补齐两者桥接与动作启动门禁。当前取消仍会立即尝试关闭工具状态；若后续改为延迟清理，需先验证运行中工具返回、结果登记和清理之间的并发顺序。

统一收尾时，沿用现有 Run 结果到检查点的关系：`completed` 使检查点进入 `done`；`blocked` 使其进入 `blocked`；`stalled`、`exhausted`、`runtime_error` 和 `interrupted` 保持可继续的 `in_progress`。TaskStore 的提交状态仍由 Runtime 管理，不由这张映射推导。

## 4. 每轮执行顺序

```text
Runtime 绑定 Task / Run
  → 初始化运行状态、会话和检查点
  → 冻结本轮可见能力
  → 检查取消和预算，调用模型（含传输重试）
  → 记录模型回复
  → 逐个处理动作：可见性 → 去重 → 预检 → 委派限制 → 策略/审批 → 执行
  → 成功切换工作区时先更新活动根
  → 每个结果经同一入口投影到会话观察、证据和阻塞
  → 判断完成、恢复提示或下一轮
  → 唯一收尾入口确定 outcome、checkpoint 和资源释放
```

动作执行应返回一个内部结果，说明实际执行、拒绝或跳过的事实；它本身不追加会话历史。保持现有去重、预检和委派检查的优先级，以保留错误结果和安全门禁行为。工具注册表继续负责真实执行的日志、观察归档及结果元数据；引擎入口只负责把结果投影到运行内会话与检查点，合成结果沿用现有日志路径，避免重复事件。工作区切换和缓存失效顺序必须保持现有观察归属。审批通过只允许该动作继续到执行门禁，不等于工具成功；工具结果仍决定证据和完成状态。

## 5. 必须保持的不变量

1. **单次运行单一写入顺序**：同一 Run 的模型回复、动作结果和检查点更新按顺序发生；Task 取消接受与新动作门禁由 TaskStore 排序，已启动动作的结果仍先登记再收尾。
2. **结果先于结论**：实际执行结果进入观察与检查点后，完成裁决才读取证据。模型 `done` 只是候选完成信号。
3. **审批不扩大授权**：审批绑定原动作和工作区；修改动作、切换工作区或恢复运行后，按现有规则重新检查。路径授权和动作审批分开。
4. **重试分域**：模型传输重试可以在预算内进行；工具副作用是否可重试只能依据执行结果与现实状态判断。取消或不确定副作用不得被普通重试掩盖。
5. **单一引擎终态**：完成、阻塞、耗尽、取消和运行错误都通过引擎内同一收尾流程生成结果；引擎资源清理只执行一次。Runtime 的持久化、日志定稿和通知保留各自职责与现有顺序。
6. **持久化兼容**：现有检查点、会话、Task 记录、错误码和公开调用行为不变；内部状态对象不直接序列化为新契约。

## 6. 渐进迁移

| 阶段 | 改动 | 验收重点 |
| --- | --- | --- |
| A. 固定行为 | 用已有测试加少量故障场景锁定批准/拒绝、工作区切换、重复动作、证据失效、取消与终态 | 同一输入的结果、检查点、授权和日志关键事件保持一致；覆盖取消与工具返回并发 |
| B. 统一结果投影 | 把各动作分支中重复的会话追加、观察与检查点投影收敛到一个内部入口；保留工具注册表的执行日志 | 真实执行、预检拒绝、审批拒绝、重复结果各产生一次模型可见结果和检查点更新，不重复执行日志 |
| C. 隔离 Run 临时状态 | 将散落的计数、缓存与终态收进每次新建的运行状态，保留 Task 级共享 `ExecutionContext` 绑定 | 同 Task 相邻提交共享 Task 控制但不串 Run 计数和终态；取消和预算行为不变 |
| D. 提取动作处理 | 按现有优先级组织预检、委派检查、策略、审批、执行、工作区更新和路径授权 | 禁止动作无副作用；切换后观察归属一致；审批后仍重新受执行约束 |
| E. 收敛完成与收尾 | 将完成门禁与引擎终态生成聚到单一路径，复用现有 `CompletionPolicy` | 模型声明不能覆盖失败；引擎只收尾一次；Runtime 仍在提交后通知 |

每阶段独立修改并运行对应测试；不在一次改动中重写整个循环。只有发现跨 App、Cloud、Agent 的请求/响应字段、错误码或字段语义确实必须变化时，才另行说明兼容影响并征求确认。

## 7. 当前落地

`run_state.py` 保存单次 Run 的计数、缓存和终态，现有 `ExecutionContext` 继续承载 Task 级取消绑定。`model_turn.py` 负责模型请求与预算，`actions.py` 保持动作门禁顺序，`results.py` 统一会话与检查点投影，`turn_decision.py` 负责完成与进度裁决，`finalize.py` 统一引擎内收尾。`engine.py` 保留装配、循环和既有兼容入口；Runtime 的持久化与通知路径未变。

运行预算仍在上下文初始化后开始计时；模型请求、重试、工具执行计入预算，同步审批等待不计入。动作资源检查、审批和实际执行已归入动作模块，引擎只保留少量旧内部调用的兼容入口。

本节描述 2026-10-23 同进程职责拆分的落地状态。Task 取消桥接和动作门禁的后续落地见第 8 节；可恢复异步审批仍未实施。

## 8. 后续执行边界收敛（2026-10-28）

在已有 TaskStore 的运行中，真实工具调用在进度回调之后、进入工具注册表之前经过内部启动门禁；有副作用动作同时登记为 `started`。Task 取消接受与门禁使用同一数据库写事务顺序。取消先提交时，动作不得启动；动作先通过门禁时，它属于取消前已获准的进行中工作，返回结果仍须记录。只读动作通过门禁但不额外写入动作账本。有副作用动作的内部日志通过动作标识关联登记记录和参数制品。Runtime 在接受取消后通知对应的活动执行上下文；执行引擎在模型轮次和每个动作前继续检查该信号。无 TaskStore 的直接引擎调用保留现有内存取消路径。

动作结果进入 Run 会话与检查点后，确定性结果把记录改为 `finished`；超时、协议/传输失配，以及有副作用命令的非零退出把记录改为 `uncertain`，进程中断可能留下 `started`。测试命令同样可能产生部分副作用，非零退出也须核对；测试失败结果仍保留用于诊断。存在未知动作时，同一 Task 暂停新的有副作用动作，待原提交停止并完成外部核对；只读动作仍可用于核对。启动记录与动作指纹、经统一脱敏的参数摘要在同一事务内持久化，因此后续日志失败时仍有核对依据；不保存原始参数或输出正文。它不是跨进程恰好执行一次保证，也不为外部系统伪造幂等能力。

取消接受点之后立即通知执行上下文并尝试清理工具。清理失败仅记录诊断，不改变已接受的取消；工具状态保持待清理，后续取消或运行收尾可再次尝试。清理成功后才标记已关闭。

模块边界继续收敛：协调器只负责轮次推进；动作流程使用显式依赖处理可见性、审批、启动与结果；完成裁决读取已记录事实。先用故障注入测试验证取消竞争和结果未知，再扩大到更多执行目标。运行诊断从现有事件派生阶段耗时与无效轮次指标，不更改 App、Cloud、Agent 请求/响应字段或错误码。

资源清理逐项尝试，一个关闭失败不阻断其他资源。已清理的临时状态移除，失败项保留；同一清理重试不重复关闭已成功的持久状态，全部成功后才结束该次清理。

## 状态与恢复的约束

- 执行返回、文件现状和可信核对结论分别记录；文件匹配或缺失不能推导历史动作是否发生。
- 同一 Task 同时只能有一个提交持有执行权；领取检查与状态变更在同一写事务完成。
- 副作用失败默认保持未知；只有可信内部阶段证明尚未执行时，失败才可安全结束。陌生错误码、远端 metadata 和工具名称均不能提供这一证明。
- 观察不授权重放；只读观察可继续，未知副作用须等待可信核对。文件观察与裁决追加留存，裁决要求主体及证据。
- 每次运行至多携带 8 条最新文件观察，路径显示限制 240 字符，并明确观察可能失效。它不替代执行前校验。

运行取消在锁内校验绑定上下文，清理仅使用该上下文持有的工具；上下文切换、清理和会话状态准备共用资源锁。执行权释放覆盖上下文绑定阶段，绑定前中断也不得遗留执行锁或取消上一个上下文。正常会话关闭经过引擎统一入口，执行中拒绝普通清理，取消仍可请求中断。Runtime 停止接受任务与资源清理完成分别记录；清理失败可重试，强制关闭的收尾异常不覆盖已有中断或执行结果。

每次调用返回独立、不可变的执行阶段凭据；合成授权拒绝保留原调用未启动事实，实际重试使用新调用自己的凭据。只有只读动作或可信阶段证明未执行的动作，才可在授权扩展后重试。命令执行后报告工作目录越界时不重放。工具资源代际、进程组清理和平台边界见[工具执行与资源生命周期](../reference/tool-execution.md)。

本机执行权回收仅适用于原进程身份可验证且从未登记副作用动作的提交。父进程退出不证明子进程或远端效果停止；已有动作记录的崩溃提交继续保留门禁，具体约束见[执行账本](execution-ledger.md)。
