## 目标与当前判断

目标是把 SaiWorks 从由 CLI/TUI 驱动的 Agent 程序，重构成可被 TUI、Desktop、Voice、Mobile 稳定消费的独立 Execution Runtime。壳负责人与系统交互，内核负责完整执行语义和可靠状态。

当前无终端装配与主要运行职责迁移已完成；B/C 主体迁移完成，但验收未闭合。不能宣称多壳稳定消费或壳关闭后继续执行已经实现。D/E/F 尚未实现，其中 D 的同步与审批具体契约仍待用户确认。

## P1：已复现的 B/C 可靠性缺陷

### R1：同一 Task 多个已接受提交排队时，后续提交失去执行上下文

- 触发：同一 Task 的两个不同 submission 先完成接受，再依次进入同一 Runtime 执行队列。
- 机制：任务库允许同 Task 多个 queued 提交；首个执行结束清除按 Task 保存的执行上下文。后续提交先被标为 running，随后读取已删除的上下文，且读取位于异常收尾保护之外。
- 复现：临时 SQLite 库配合受控引擎与两个执行线程，首个任务等待释放信号，第二个排队；首个结束后第二个抛出 KeyError，任务库仍为 running，实际未执行。
- 风险：已接受请求没有可靠终态；恢复时会被当作需要核对的执行中尝试。
- 代码：src/saiworks/runtime.py 的 execute，上下文读取与 finally 清理；src/saiworks/sessions/tasks.py 的接受和 claim。
- 修复方向：明确 Task 与执行尝试的资源生命周期，保留仍被排队尝试引用的资源；所有取得执行权后的准备失败必须进入统一收尾。
- 验收：同 Task 两个已接受提交串行执行，均有准确结果；准备阶段异常不遗留虚假的 running，重复提交不产生重复副作用。

### R2：完成通知早于权威结果持久化

- 触发：引擎返回执行结果后，任务库结果保存失败。
- 机制：内部执行先发出结束观察通知，外层随后保存任务结果。两者顺序允许壳已展示结束而任务库仍为 running。
- 复现：结束观察者读取任务库状态为 running；将结果保存模拟为 OSError 后，调用失败，已发出的结束通知无法撤回，数据库仍为 running。
- 风险：展示与权威状态矛盾；恢复或重试若缺乏执行事实核对，可能重复已发生的外部动作。
- 代码：src/saiworks/runtime.py 的 _execute 结束通知与 execute 结果保存。
- 修复方向：权威状态持久化之后再通知；区分执行结果与持久化失败，保留已执行事实，不以重新执行掩盖保存失败。会话、日志和任务库之间的失败一致性也须核对。
- 验收：保存失败不向壳发布已持久化的终态；查询能准确说明结果与保存状态；重试不重放已有副作用。

## B/C 剩余边界问题

| 编号 | 当前差距 | 风险与验收方向 |
| --- | --- | --- |
| R3 | 通用执行与会话执行的保存流程不同，部分调用者需额外调用保存或准备步骤 | 新壳遗漏步骤导致会话或恢复语义不同；各入口应消费统一完整执行流程 |
| R4 | 观察回调为单个可覆盖字段，并在执行线程同步调用 | 后接壳覆盖前接壳，慢观察者拖住执行；多观察者与慢消费者隔离在 D 验收 |
| R5 | 取消主要面向当前执行，而非稳定 Task 身份 | 多客户端可能取消非目标任务；D 明确目标、接受时点及 Cancel 优先规则 |
| R6 | 展示视图保留旧引擎对象形态，能力管理仍含终端命令语法 | 新壳容易依赖兼容结构；后续形成面向任务的查询与控制边界，避免壳承担执行逻辑 |

R3 须先核对 B/C 完整流程；R4/R5 的多客户端能力按已确认阶段规划在 D 完成，不将规划中的能力写成当前保证。R6 为维护风险，不能仅凭结构相似认定执行错误。

## 计划内尚未实现的能力

- D：Snapshot + 单调 revision、重连与重新同步、多观察者、审批持久化与 TTL、等待释放执行槽、continuation、控制权限、取消与批准竞态。
- E：常驻 Runtime、自主推进已接受任务、壳关闭后继续执行、实例发现、managed/attached ownership、Gateway 重启语义与崩溃恢复。
- F：Companion 接入与交互体验。Model Core、Gateway、Manager 不因本次模块提取而自动成为已实现服务。

当前接受能够持久化身份，但单独接受并没有建立常驻执行机制；执行仍依附调用线程与进程。同步审批仍通过展示回调完成，尚无可靠的等待与重连协议。这些是阶段缺口，不是本轮新增回归。

## 模块与壳职责

当前核心七项职责为 Runtime、Execution Engine、TaskStore、Session Coordinator、Context Compaction、Capability Runtime、Runtime View；均为同进程模块，原有模型、工具与安全模块继续复用。

壳应只收集意图与上下文选择、展示状态、提交审批和取消请求、管理界面。内核应独立承担接受去重、绑定上下文、会话一致性、预算、权限、动作、等待、收尾与恢复。换壳不应要求重建运行流程。
