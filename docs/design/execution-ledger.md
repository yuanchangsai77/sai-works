# Execution Ledger

状态：目标设计。当前证据与恢复机制见[Evidence & Recovery](../runtime/evidence-recovery.md)。

## 目标事实链

```text
Task / Run / Step
   → Proposal → Permission → Execution → Result → Evidence
   → Checkpoint → 后续运行
```

账本应让人可以检查操作为何获准、实际发生什么、结果支持哪些交付、从哪里继续。诊断事件、完整制品和有界恢复投影分别保存，使用关系关联，避免复制无界正文。

## 查询与操作

Inspect 与 Compare 消费记录，不产生新副作用。Resume 重建仍有效工作集；Fork 建立独立分支；Replay 必须区分只读展示与再次执行；Rollback 仅针对有补偿能力的目标。

任务状态、权限与资源版本各有权威所有者，账本关联它们，不创建第二套完成或授权状态。旧授权不能因为历史存在而重新有效。

## 访问与保留

记录与 artifact 需按任务、会话、资源和授权核对访问。引用不是许可。秘密不写入账本；来源、完整性、保留与删除需明确。不可变、哈希链或签名属于可选实现，不能代替执行事实质量。

## 实现与验收缺口

当前已有日志、trace、checkpoint 与证据关联，但没有完整账本查询和所有动作级授权记录。先验证一个失败后恢复闭环，再扩展查询、分叉或补偿。验收覆盖部分成功、失败结果、过期观察、跨会话访问和不确定副作用。

2026-10-28 的最小落地只为有 TaskStore 的真实工具调用保存启动与结果边界，并与取消接受排序。进程中断留下 `started`；超时、Shell 协议失配、无法确认执行结果的 MCP 传输错误，以及有副作用命令的非零退出留下 `uncertain`。测试命令非零退出同样须核对，失败结果仍保留用于诊断。任一有副作用动作处于这两种状态时，同一 Task 的后续有副作用动作均暂停，避免模型通过调整超时或其他参数绕过核对；只读核对仍可进行。Shell 和测试命令的逻辑身份不包含超时参数。启动记录在同一事务内保存动作指纹和脱敏参数摘要，日志失效时仍可提供核对线索。可信执行方必须先确认该 Task 没有正在运行的提交，再根据外部状态把未知动作记录为已发生或未发生。已发生的同一逻辑动作不得自动重放，未发生动作可以重新申请启动。此处不提供面向 App、Cloud、Agent 的核对入口；完整授权链、查询 API 与补偿仍属于后续阶段。

不在本页新增记录 schema 或宣称日志已提供完整防篡改审计。
