# 授权交互与审批传递

状态：待实现设计。当前同步回调与后台阻塞见[Policy](../runtime/policy.md)；本页不新增审批消息字段或签名协议。

## 目标

让 CLI、TUI、Desktop、远程界面与子代理使用同一授权语义。Runtime 产生待决定动作，壳呈现具体范围并转交人的决定，Runtime 校验后执行。

Policy 可直接允许的动作无需人为确认；需要人的授权不能由模型或代理自行替代。传递审批是转交交互，不是新的授权主体获得无限批准能力。

## 必须明确的语义

请求需关联主体、任务、实际动作、资源、目标与约束。决定只能适用于该范围；修改动作、资源、工作空间或恢复条件时需核对仍否有效。

需要区分拒绝、尚未回复、取消、过期和运行失败，不能把没有答案当成允许。任务取消后迟到批准不能启动旧动作；撤销和恢复不能隐式复用无效决定。

## 交互与后台运行

不同壳可以用不同 UI，但共享请求状态与验证。无交互后台遇到未获许可动作时保留阻塞与证据，而不是自动提权或反复调用模型猜测权限。

子代理可向父任务提交额外权限需求，由父任务在已有用户范围内处理；跨设备决定依赖共享信任事实。不能从公共摘要读取一句“已批准”作为可执行许可。

## 设计与验收顺序

先定义状态关联、有效性、并发和取消，再协商消息契约和传输。验收覆盖重复决定、迟到回复、篡改动作、重连、任务续跑和授权撤销。现有 run 内审批复用规则在替代方案确认前保持原行为。
