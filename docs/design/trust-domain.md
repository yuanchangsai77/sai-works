# 共享信任域

状态：目标领域设计，未冻结 wire schema，不宣称已有统一身份与票据系统。

## 领域与责任

Shared Trust Domain 包含 Principal、Device、Resource、Credential、Permission、AccessTicket、AccessSession 的身份、访问和连接语义。当前先作为共享 Domain / Protocol，不预设独立 access-core 服务。

| 边界 | 决策 |
| --- | --- |
| 身份与访问 | 谁、哪台设备、通过什么凭据访问什么资源，多久有效 |
| SaiWorks 执行 | 该主体是否可在此目标对资源执行具体操作 |
| Model Core 推理 | 是否可使用模型、部署或算力，以及容量与额度 |

## 目标访问过程

长期凭据用于认证，短期可验证票据用于建立受限访问会话；资源验证身份、范围、有效期与撤销条件。加密、远程连接和访问审计支持这条边界，不把 SSH 连通性视为全部权限。

票据只证明其明确授予的访问事实，不能替代动作 policy。远程主机的执行资源与 GPU 推理资源分别管理。

## 所有权与恢复

凭据与签名秘密不进入模型上下文；两个 Core 消费必要可验证事实。撤销、过期和断线后重新连接不得扩大授权。执行记录关联访问事实，但不复制秘密。

算法、票据字段、撤销协议和 transport 尚需跨项目协商；本轮仅确定领域责任，不变更现行接口。只有出现独立生命周期、部署或发布需求时再拆服务。

当前本地模式、路径授权和委派合同见[Policy](../runtime/policy.md)，它们不是共享身份系统的完整实现。

## 策略来源与数据范围

用户配置和偏好可以收紧使用范围，不能覆盖组织、系统或目标本地的硬限制。组合策略需要可验证来源；远端描述或模型观察不能提升来源等级。

认证能力不足时保持受限动作等待，不能为了恢复连接降低认证强度。多主体共享资源需核对资源所有权和适用约束，不能仅凭发起者可登录就推导可以影响其他主体。

原始敏感数据、派生摘要和索引遵循同一授权分类。跨域查看与跨域计算分别核对数据许可；删除或撤销应覆盖派生访问路径，引用不能继续提供访问能力。
