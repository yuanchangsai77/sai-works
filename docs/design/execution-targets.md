# Execution Target 与分布式演进

状态：目标设计。当前本地工具与 MCP 适配见[Execution Runtime](../runtime/execution-runtime.md)。

## 目标模型

Execution Target 表达操作实际发生的资源环境；Executor 表达执行适配；Capability 描述可以请求的操作。文件系统、Shell、浏览器、数据库、设备和容器是可能的能力与目标组合，不预设固定工具清单。

目标需关联身份、可用能力、约束、环境、容量与生命周期。Workspace 使用这些资源，但不自动拥有目标全部权限。目标可访问不代表所有操作可执行。

## 本地到远程的依赖

先明确本地动作状态、资源范围、结果与不确定副作用，再接入远程身份与访问，最后建立节点容量、租约、调度和崩溃协调。调度选择资源，不拥有第二套任务完成状态。

同一 Remote Node 的执行与推理分别供两个 Core 使用，不能合并额度与权限。远程访问协议和执行提交协议是不同边界。

## 失败语义

连接中断、接收失败、执行失败、执行成功但结果丢失是不同情况。目标若不能提供幂等或状态核对能力，Runtime 必须保留不确定状态并请求受约束协调，不能盲目重发。

租约过期或节点重启后应核对工作是否仍在运行；任务取消和迟到结果需防止覆盖新状态。Sandbox 需提供真实限制和可验证环境，不以进程组管理替代。

## 首个闭环与退出条件

选择一个真实远程或非 Coding 场景，经统一授权、执行、结果、证据与恢复路径完成。注入断线、超时、进程崩溃和撤销，验证约束不扩大与副作用不盲目重复，再决定独立 worker、服务或调度器部署。

本页不冻结节点协议、租约字段、队列实现或分布式锁，也不承诺通用回滚。

## 值得保留的执行约束

能力实现绑定与节点选择是两步：先匹配操作语义、数据域和授权约束，再在合格节点中选择执行资源。性能评分不能覆盖硬约束，执行目标在真正产生副作用前还需本地复检。

无状态或幂等操作可以按约束重新绑定；有状态流、长事务和不可逆动作必须先确认旧执行状态，再考虑迁移或补偿。

| 竞态 | 目标处理语义 |
| --- | --- |
| 取消与完成同时发生 | 记录权威先后；取消不能抹除已经发生的效果 |
| deadline 到期但结果迟到 | 停止新的执行承诺，保留实际结果用于核对 |
| lease 过期后旧节点恢复 | 可以报告历史效果，不能据旧租约取得新执行权限 |
| 确认丢失 | 查询权威执行状态，无法证明未执行时不盲目重发 |
| 排队或恢复时授权变化 | 执行前重新判断，不复用已经无效的决定 |

幂等记录需明确作用域与保留窗口，覆盖实际执行和断线恢复范围；窗口过后不能假设仍能识别重复。跨节点时间戳用于展示不等于可用于授权与排序，需权威状态或明确时钟条件。

设备接受命令、开始执行、观察到效果、验证期望状态是不同事实。只验证下发时应说明现实效果尚未确认。这些是待实现语义，不新增当前状态枚举。
