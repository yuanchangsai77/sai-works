# 系统协议边界

状态：目标边界梳理，不定义新消息字段、错误码或 transport。

## 哪些边界需要协议

| 边界 | 稳定语义 | 当前情况 |
| --- | --- | --- |
| Interface ↔ SaiWorks | 任务控制、会话、观察、授权交互与证据访问 | 同进程调用与回调，完整门面待整理 |
| SaiWorks ↔ Model Core | 推理需求、动作协议、请求生命周期 | 现有模型传输参考，需求发现尚需协商 |
| Core ↔ Shared Trust | 可验证身份、访问范围、有效性与撤销 | 目标共享域，非已实现票据 API |
| SaiWorks ↔ Execution Target | 受限执行、状态核对、结果与取消 | 本地工具/MCP 已有部分路径，通用目标待设计 |
| Runtime ↔ Artifact Store | 引用、授权、保留与完整性 | 现有归档，统一访问边界待完善 |

同进程模块直接使用内部接口，不为了统一强制走网络。跨进程、跨设备和信任边界才增加协议与访问控制。

## 共有设计约束

先确定状态所有权、请求关联、重试、取消、幂等、不确定结果及版本兼容，再确定 JSON、RPC、事件或具体 transport。大型数据走受控引用，不能塞入无界控制消息。

协议转换不拥有新的业务决策，消费者不能把展示事件当成授权。事件交付保证与断线恢复位置必须根据实际来源能力验证，不能从旧设计继承默认保证。
