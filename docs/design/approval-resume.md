# 等待与续跑的剩余设计

状态：持久化等待、执行槽释放、预算续接、单动作批准消费及用户回复已并入[现行机制](../runtime/agent-runtime.md#等待与续跑)，具体字段只见[控制参考](../reference/runtime-control.md)。本文只保留未闭合的跨界面、子代理交接及外部工具状态边界，不维护工作状态或重复定义现行接口。

## 跨界面等待接管

CLI、TUI 和桌面的同步兼容适配已能在槽外收集决定；目标是各入口完整消费同一任务快照、修订与控制资格，观察重连不重提任务，也不重复弹出已经裁决的问题。窗口断开与进程退出必须区分，关闭窗口后自动续跑仍依赖独立服务生命周期，不由已有显式恢复能力承诺。

## 子代理问题交接

委派子代理沿现有父代理交接路径说明缺失决定，不直接暴露人类提问工具，不能令父代理隐藏地阻塞在不可见问题上。未来父代理若转交问题，应保留任务关系、决定作用域和原调用身份，父级回答不得扩大子代理权限。具体跨任务消息或字段变化另行协商。

## 外部工具状态恢复

当前等待关闭普通工具状态，不能复活 Shell 环境、连接或远端事务。需要保留外部长进程时，应由明确的执行目标负责可查询身份、停止与恢复语义；不能序列化进程对象、重建有副作用的启动命令，或把新进程存活当作原动作成功。

以上边界不发布网络 API，也不把日志和检查点解释为任意动作可重放。当前回归入口见[等待回归](../../tests/test_runtime_waiting.py)，真实模型、GUI 和跨设备验收分别需要独立证据。
