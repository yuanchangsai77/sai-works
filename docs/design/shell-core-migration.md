## 2. TUI 拆分范围

保留：终端渲染、输入编辑、历史和补全、TTY 检测、展示投影、瞬态预览、会话选择界面、审批选择界面。

迁出：会话持久化协调、恢复校验、运行总结与终态收尾、子任务运行工厂及授权核验、上下文压缩的运行政策、状态与证据查询、取消协调。

混合职责分拆：压缩是否需要以及如何落盘归 Runtime，用户选择归壳；斜杠命令解析归壳，其激活能力和恢复操作归 Runtime；终端信号转成运行控制请求，终态由 Runtime 产生。

不拆成多个服务：初期 Runtime 门面与执行内核同进程，复用 store、guardrails、checkpoint 和进度抽象。目录搬迁不是完成标准，业务职责迁移才是。

## 3. 分阶段实施与验收

### 阶段 A：确认拆分决策与核对兼容行为

首版决策已确定：整个 Runtime 单执行槽；同 Session FIFO；每个 Task 独立 execution context、cancellation token、工具运行态与审批；Accepted 是任务身份、Bound Context 元数据和 submission identity 去重记录的一致持久化完成；Accepted 不代表 Running；Shell 只做展示投影，Runtime 唯一收尾。

本阶段只核对安全拆出 CLI/TUI 运行职责所需的事实：普通交互、单次执行、后台子任务、审批、取消、失败保存、恢复和非 TTY 的实际路径与测试覆盖；明确既有 Task/run/session 及证据关联。审批、同步和服务管理的行为决策已记录在边界设计，详细契约和实现分别在 D、E 前完成，不把它们全部作为 B/C 的前置工作。

交付：现有语义核对结果、B/C 职责迁移清单、持久化接受与去重设计、兼容性影响和行为验收场景。新增字段、错误码、状态语义或持久化格式的具体变更先说明影响并确认，不将行为概念直接发布成 API。

退出条件：单执行槽、同 Session FIFO、Task 隔离、durable acceptance、submission id 去重、无终端 Runtime 和唯一收尾已有可实施设计；相关现状核对和必要契约确认完成。决策已确认不表示现有代码已实现或行为测试已通过。

### 阶段 B：提取无终端依赖的 Runtime 装配与协调

从 app.py 的现有装配拆出不创建 Presenter、不返回 CLI 的运行对象。从 cli.py 迁移会话协调、保存、恢复和收尾；子任务工厂使用运行对象，保留既有委派权限核验。复用已有引擎和 stores。整个 Runtime 只开放一个执行槽，同 Session FIFO；即使串行也将取消、执行上下文、工具执行实例和审批状态隔离到 Task。工具定义与基础身份资格可共享，具体批准绑定 Task + Action。现有子代理保留独立 Runtime 实例，单执行槽按实例生效，避免父任务同步等待同槽子任务。B/C 期间现有 run 内审批复用规则保持兼容，D 再以经确认的 Task + Action 有效性校验替代。

进度先经运行适配转到现有 Presenter；审批保留兼容路径，同时将决定的执行校验留在内核。不引入 HTTP 服务来掩盖同进程职责问题。

接受路径先一致持久化 Task Identity、Bound Context 元数据与 submission identity 去重记录，再确认 Accepted 和进入排队；未完成接受前不得执行副作用。同一 submission id 重试返回原 Task，内容冲突不能静默通过。

验收：Runtime 同时最多一个执行任务，同 Session 顺序稳定；取消与工具状态不会污染下一任务；接受确认丢失或接受过程中崩溃不创建重复任务；无 stdin、stdout、TTY 和 Presenter 时可运行并持久化；正常、失败、中断均只收尾一次；后台子任务无需创建 CLI。既有会话数据仍可读取，旧入口行为通过相应回归场景。

### 阶段 C：让 CLI/TUI 成为门面消费者

替换壳对引擎内部状态、内部收尾和存储协调的访问。保留渲染，使用运行查询产生的展示数据；把中断转为运行控制。逐项迁移斜杠命令，禁止另建执行或审批旁路。

验收：CLI/TUI 无需调用引擎内部收尾；审批拒绝、取消、失败不会留下伪完成视图；单次、非 TTY、交互终端仍可用。检查依赖方向，运行核心不导入终端展示模块。

### 阶段 D：快照修订与可恢复审批

实施前完成具体契约：一致 Snapshot + 单调递增 revision、重新同步、审批 TTL、等待释放执行槽、Cancel 优先于 Approval、多客户端观察与控制权限分离。定义 revision 的状态范围，不要求完整持久化事件日志；任务状态、审批、artifact、结果、错误和执行事实必须可恢复，token preview 不保证重放。SaiWorks 管理 artifact identity 和任务关联，实际内容可在 workspace 或 object store，Shell 不保存唯一副本。

进入 WaitingApproval 前持久化 continuation/checkpoint，再释放执行槽；默认不保留模型连接或工具进程，外部长进程单独受管。等待不计执行/模型预算，单独计算可配置 TTL；Approval 过期后 Task 仍可恢复，不自动执行或默认失败。其他 Session 可使用空闲槽，同 Session 后续任务不能越过等待任务。continuation 保留已消耗的任务预算，续跑不得重置；批准后重新排队、获取槽并复核有效性；取消接受后迟到批准不得启动新动作。

先验证同进程客户端，再接跨进程传输。验收：快照与订阅间的变化可发现；重复、缺口、慢客户端和断线后可重新同步；两个观察者看到相同权威终态；审批等待期间其他 Session 可运行；过期、批准与取消竞态有一致结果；观察权限不能用于控制；文本预览丢失不影响结果与证据。

### 阶段 E：独立服务生命周期与薄 Gateway

实施前完成具体契约：managed / attached、已有实例发现、Manager ownership、Gateway 重启语义、SaiWorks 崩溃恢复、版本兼容与部分就绪。Manager 默认 attach 已有健康实例，通过实例锁或等价机制避免启动竞争；只可停止自己启动且持有 ownership token 的进程，attached 实例只断开连接。

Model Core 默认可共享常驻，Desktop/TUI 退出不自动关闭它。SaiWorks 首版为单用户本地 Runtime，生命周期独立于 Shell。Gateway 只负责转发、认证接入、版本适配与聚合；重启后重新查询 SaiWorks 快照，不恢复、重建或重试任务。第一版不扩大到远程设备访问。

验收：关闭 Shell 后任务继续；多个入口不会重复启动实例；退出入口不停止 attached 服务；Gateway 重启不重新创建任务；SaiWorks 崩溃后已接受 Task 仍存在，先核对恢复条件与未知动作结果；Model Core 不可用时准确表达受影响能力。阶段 B/C 先完成生命周期边界，常驻续跑在 E 才验收实现。

### 阶段 F：Companion V0.1

增加全局快捷键、轻量输入栏、工作区选择、任务进度、审批和结果查看。先支持明确选择的工作区；自动识别当前应用只有在可核实并允许采集时启用。

验收链路：选择工作区 → 绑定上下文 → 提交 → 观察 → 批准或拒绝 → 结果/证据。另起执行中任务验证取消；在运行或审批等待期间关闭并重开客户端，恢复同一任务视图。完成任务后的取消不应成为主链路步骤。

## 4. 必要行为验收矩阵

| 场景 | 通过标准 |
| --- | --- |
| 提交后用户切换项目 | 执行仍使用已绑定工作区 |
| 提交文件上下文后文件变化 | 内容快照或版本语义可解释，不伪称冻结 |
| 提交接受确认丢失 | 可核对原任务，重试不重复执行副作用 |
| 审批等待与过期 | 释放执行槽，其他 Session 可运行；过期不执行，Task 保持可恢复 |
| 多个入口发现服务 | attach 已有健康实例，只有持有 ownership 的 Manager 可停止 managed 进程 |
| 审批期间关闭客户端 | 无批准不执行，重连可查看待审批动作 |
| 两客户端提交不同决定 | 内核给出一致裁决，不重复执行 |
| 批准与取消同时到达 | 取消接受后批准不能启动新动作；此前已启动动作核对停止与结果 |
| 工具不响应取消 | 不伪报已停止，保留不确定执行事实 |
| 通知重复或 revision 出现缺口 | 去重或重新同步，权威状态一致 |
| Gateway 重启 | 任务身份、状态和审批不由 Gateway 重建 |
| 内核在外部动作后崩溃 | 核对结果再恢复，不盲目重放 |
| 无终端运行与旧会话加载 | 不依赖 UI；现有数据兼容 |
| Model Core 不满足硬约束 | 不静默放宽隐私、位置或预算 |

上述矩阵横跨 B 至 F，不能整体标为已通过。B/C 已验证项与未闭合能力见阶段核对。优先复用已有测试，只补保护生命周期、权限和重连行为的必要测试。

## 5. 兼容迁移与回退

每阶段保留可运行的旧用户入口，逐步改为门面适配；临时兼容适配有删除条件，不长期维护第二套状态机。持久化变化先检查旧记录读取与版本兼容。回退只回退入口或装配，不自动重新执行已接受任务。

旧 CLI 随进程退出的行为与常驻任务脱离客户端的行为需在发布说明中分开表达。当前 Model Core Electron 看板继续作为管理入口，其退出停止后端的现行机制不能直接当作 Companion 常驻实现。

不要复制多份“正式契约”；字段和错误码经确认后归唯一接口参考，设计文档链接它。源码核对表随实现推进更新，区分目标、已实现、已验证。

B/C 已迁移无终端装配、单槽与 Task 隔离、持久化接受、去重、会话及命令协调和收尾职责；可靠性验收仍有缺口，见[临时审查问题记录](shell-core-review-temporary.md)。先闭合 B/C 缺陷，再进行阶段 D 的[具体契约确认](runtime-sync-approval-contract.md)，随后实施修订同步与可恢复审批；常驻和 Companion 分别在 E、F 验收。
